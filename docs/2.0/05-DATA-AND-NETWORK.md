# 身份、存档、迁移与联机契约

状态：2.0 目标契约，M0 定稿格式、M1/M4 验证。当前 v27 读写行为见[基线](research/BASELINE.md)。

## 身份与资产归属

| 对象 | 稳定身份 | 权威归属 / 可携带内容 |
|---|---|---|
| 玩家 | Player ID | 可导出的身份材料与显示资料；设备更换不换人 |
| 设备 | Device ID | 可撤销设备会话；不等同玩家身份 |
| 世界 | World ID | 规则、地籍、账本和历史；由唯一写入者推进 |
| 农场 | Farm ID | 在某 World ID 内归属玩家或组织 |
| 房间 | Room ID | 会话与访问入口；更换地址不改变世界身份 |
| 联系人 | 对方 Player ID | 别名、联系地址、关系证明与屏蔽偏好 |

身份密钥方案是候选，须在 P0 验证签名、备份、轮换和丢失恢复。公开 ID 不由电脑用户名、文件路径或硬件序列号派生。设备授权与主身份分离，丢失设备后可撤销会话；主密钥完全丢失且无恢复材料时，不能承诺无条件找回所有独立房间的资产。

好友列表可以迁移，好友的在线状态需要可达服务器或可选目录服务；独立房间之间不存在默认全网发现。关系确认由双方身份与房间记录证明，不能仅凭同名认定旧好友。

## 可导出包

世界包包含格式版本、规则版本、World ID、导出时间、已提交序号、对象清单、快照、必要事件尾部及内容摘要。资源引用使用稳定资源 ID 与版本，不记录本机绝对路径。自定义资源若获分发许可可随包，缺失资源应列出并提供占位呈现，不能丢弃相应权属和库存。

身份包独立加密导出，联系人和设备授权记录随身份迁移；云端 API 密钥、临时会话令牌不混入普通世界包。世界公开备份不包含玩家私钥。导出界面解释包的范围、密码与恢复方式，并允许校验后查看摘要。

金额和离散数量使用明确范围的整数；超过 JSON 精确整数范围时采用约定的十进制字符串。时间包含单位与 UTC 语义。排序、随机种子、舍入和事件版本必须可重放；视觉浮点差异不参与交易判定。

## 导入与版本演进

导入包作为不可信数据处理：限制解包大小、拒绝越界路径和可执行内容，先按明确 schema 解析；摘要用于完整性校验，身份真实性另由验证过的身份材料证明。

导入流程为读取到隔离区、验证摘要与版本、检查资源与身份归属、展示将创建或替换的世界、保留可恢复旧副本、原子切换、重新读取核对。损坏包、未知较新格式或不支持规则不得覆盖现存世界。中断后保留至少一个完整可读版本。

v27 是明确的一次性导入来源目标。M0 使用脱敏夹具建立地块、库存、布局、邻居和装饰字段映射；无法转换的字段列入导入报告，不能悄悄清空。旧 Demo 原件保持可读且不原地升级。更老版本未列入承诺；现有代码中的旧提示字段不等同存在迁移实现。

2.0 起发布格式要附支持范围与升级路径，升级前留备份。回退程序不能强行读取更高版本；回退世界须使用匹配版本快照。具体保留几个版本由发布策略确认，不能以“永远兼容”替代可执行转换。

## M0-03 契约（目标包信封 v1）

状态：信封 v1 已实现于 [`Game/farm/world_package.gd`](../../Game/farm/world_package.gd)，v27 一次性导入见 [`Game/farm/v27_importer.gd`](../../Game/farm/v27_importer.gd)；测试见 [`tests/world_package_test.gd`](../../tests/world_package_test.gd)、[`tests/v27_importer_test.gd`](../../tests/v27_importer_test.gd)。本阶段只固定标识、时间、金额、版本、快照与导入校验，不接入联网、账号或经济；现有 v27 存档读写路径不变。

### 信封字段

| 字段 | 类型与范围 | 职责 |
|---|---|---|
| `format` | 固定字符串 `yipiantian.world` | 包类型；不匹配即拒绝 |
| `format_version` | 整数，当前只接受 `1` | 信封 schema 版本 |
| `rules_version` | 整数，M0 只接受 `27` | 农场规则与快照 schema 版本；对应现有 FarmState |
| `world_id` | 1–64 个 ASCII 标识字符 | 世界、地籍、账本与历史的权威身份；由唯一写入者推进 |
| `farm_id` | 同上 | 某 `world_id` 内归属玩家或组织的农场身份 |
| `player_id` | 同上 | 玩家跨设备身份；设备更换不换人 |
| `device_id` | 同上 | 可撤销的设备会话；不等同玩家身份 |
| `exported_at_utc_seconds` | 非负整数，≤ 2^53−1 | 导出时间，Unix 纪元起的 UTC 秒 |
| `committed_sequence` | 非负整数，≤ 2^53−1 | 已提交事件序号；M0 只校验，M4 用于同步 |
| `money` | `{ "currency": String, "minor_units": Integer }` | 金额表示；本阶段只做封装校验 |
| `snapshot` | 对象 | v27 FarmState 快照，由 FarmState 完整校验并返回同语义的规范化副本，不修改输入对象 |
| `decorations` | 对象 | v27 装饰解锁与摆放状态，由 DecorationState 校验；与 `snapshot.kitchen` 的摆放约束交叉核对 |

标识字符限定为 `A-Z`、`a-z`、`0-9`、`_`、`-`、`.`、`:`，不得含空白、路径分隔符或非 ASCII 字符。公开 ID 不得由电脑用户名、文件路径或硬件序列号派生；形状校验只保证格式，来源真实性仍需 M4 的身份材料证明。

### 时间与金额

- 信封时间统一为 Unix 纪元起的 UTC 整数秒，不含本地时区；M0 接受有限整数值并在规范化时写成整数。
- `snapshot` 内 v27 既有的 `*_utc_seconds` 字段继续使用 UTC 浮点秒，由 FarmState 按现有规则校验；M0-04 迁移保留原值，不在本阶段改用新单位。
- 金额只使用整数最小单位：`currency` 为 1–16 个大写 ASCII 字母，`minor_units` 为非负整数且不超过 2^53−1。不得用浮点或四舍五入后的值记账；负数、借贷、冻结与挂起由后续账本事件表达，不塞入本字段。本版不接受十进制字符串金额，超出安全整数范围直接拒绝；后续若需更大范围，递增 `format_version` 并定义字符串编码。

### 版本协商与拒绝语义

- `format_version == 1`、`rules_version == 27` 才接受。更高版本分别返回 `newer_format`、`newer_rules`；更低版本返回 `unsupported_format`、`unsupported_rules`，因为当前没有迁移实现。非整数版本返回 `invalid_format_version`、`invalid_rules_version`。
- 未知 `format`、形状不符或 JSON 损坏返回 `corrupt`；超过 1 MiB 的输入在解析前返回 `too_large`；标识、时间、序号、金额或快照不合法返回对应的 `invalid_*`。
- 被拒绝的较新或损坏包不得改写输入字节，也不得覆盖现有 v27 存档或已接受世界。`parse()` 是纯函数，不执行文件写入；导入后的落盘与旧版本保留由调用方按导入流程处理。
- `format_version` 是新增字段的唯一入口：内容摘要、对象清单和事件尾部随 M4 事件日志实现，届时递增信封版本并定义兼容或拒绝规则，不能无版本地混入 v1。

### M0-04 一次性导入（v27 → v1）

- 只读取源目录的 `farm.json` 主件；备份、临时件和 `user://farm-v27` 正式目录不作为导入输入，也不被写入。输出固定为隔离根下的 `identity.json`、`worlds/<world_id>/world.json` 与 `worlds/<world_id>/import-report.json`。
- 源包必须为 `version=27`；较新返回 `newer_version`，更旧返回 `unsupported_version`，损坏返回 `corrupt`。拒绝时源文件字节与 SHA-256 不变，且不写入世界包。
- `world_id`、`farm_id` 由规范化 `{farm, decorations}` 的规范 JSON 内容计算 SHA-256，并分别加 `world\n`、`farm\n` 域前缀，避免同内容得到同一 ID。该内容哈希只作为一次性导入的去重键：同一源重复导入得到同一 ID 且不叠加；它不是可变世界在后续状态变化中的长期身份。长期世界身份仍按上文由首次创建分配并保持稳定，M4 若接入持久世界身份，需要为该导入世界建立稳定 ID 映射。
- `player_id`、`device_id` 在隔离根首次导入时用系统随机字节生成并写入 `identity.json`，之后重复导入复用；不读取用户名、路径或硬件序列号。它们是导入会话占位标识，不是已验证的身份密钥或设备授权会话。
- 未知字段：源信封顶层、`farm` 顶层和 `decorations` 顶层的未知键记入 `unknown_fields` 报告并从包中排除；更深层的未知键视为 schema 不符，拒绝导入并保留原件，不猜测、不静默丢弃。
- v27 没有金额和已提交序号：导入时分别初始化为 `{currency: "COIN", minor_units: 0}` 和 `0`，并在报告中注明。`exported_at_utc_seconds` 取规范化快照中最新的逻辑 UTC 秒并向下取整；没有时间字段时为 0，以保证重复导入逐字节一致。
- JSON 序列化按字典键递归排序，包与报告重复导入逐字节相同；已存在且内容不同的输出返回冲突，不覆盖。

## 跨设备与共享世界迁移

个人单机世界可 Windows→macOS→Windows 往返，比较语义状态及事件序号。复制同一世界用于实验时生成新的分支身份并标记分叉；不能让两个离线副本分别增长后自动合并成双倍财产。

共享世界迁移需暂停写入、排空已接受命令、生成一致快照与事件尾部、校验、在新服务器恢复并递增运行代次，再切换访问入口。旧服务器保持只读或关闭写入，新旧不能同时接受命令。客户端通过世界身份、迁移证明与代次确认新地址，Room ID/地址可更新，Player ID 与世界财产记录不变。

个人从房间导出的财产摘要用于查看和证明，不可在另一房间直接兑换。跨服资产流通不在首轮范围；未来如引入，必须设计源端冻结/销毁与目标端唯一领取协议。房主可提供完整世界备份，普通成员只导出有权读取的数据。

## 联机协议与权限

握手交换协议版本、规则版本、资源版本、世界身份与客户端能力；不兼容时说明需更新哪一项。所有资产命令由服务器检查身份、权限、数量、目标状态和规则版本。传输协议尚未选定，M4 比较连接维护、部署和 Godot 集成成本后记录决定。

命令使用唯一 ID，重复提交返回同一已提交结果。客户端断线后先查询最后确认序号，再补取事件或快照；不能凭“未收到成功”重新发放物品。服务器按持久化提交顺序分配序号，跨玩家交易在一个提交边界内完成。

访问、照料、收获、建设、管理分别授权。邀请可限定期限与角色，离开房间撤销相应会话；屏蔽和封禁不删除有效债权、库存或历史证据。导入的联系人数据不能自动取得新服务器管理权限。

## 最小验收场景

Windows 新建并种收后导到 Mac，修改布局再迁回；结果保持库存、地块、身份与关系。重复导入同一包不叠加奖励。复制客户端身份不能绕过服务端会话撤销。服务器写入中断后恢复不重复收获或成交。房间迁址后好友仍识别同一人；无恢复材料的密钥丢失给出准确限制。
