# P0 技术可行性试验登记

状态：方案已编写，以下六项均**未执行本轮原型、无通过结果**。仓库历史 Windows 短测见[基线](../research/BASELINE.md)，不能替代这些试验。

## P0-R1 · macOS 窗口与桌面

问题：锁定 Godot 工程能否正常窗口运行；桌面观赏与输入是否稳定？输入为当前固定提交、匹配模板和一台可确认型号的 Mac。先验证最小窗口种收，再隔离试验桌面层、Spaces、全屏切换、Dock、锁屏和多屏变化，记录系统版本与权限。

通过条件：窗口基本生活可用；桌面不抢焦点、不吞系统操作且能退出恢复。桌面部分失败时采用观赏窗口加显式游戏入口，保持 M1 可交付。产物是能力矩阵、实际运行记录和 ADR-002 的平台限制。

## P0-R2 · 三模式与能效

问题：单 Godot 与轻量外壳哪个能在保持体验下获得实际资源收益？使用同一世界、场景、镜头和硬件，测空闲、操作、遮挡、资源释放与恢复，分别报告 CPU/GPU/工作集/唤醒/功率。先对当前实现建立基线，再做候选。

通过条件：状态不分叉、无重复命令，候选资源收益在配对样本中稳定且恢复体验可接受；据此确定预算。无收益则不采用额外进程。产物为条件完整的测量表与运行形态决定，不能仅提交一张任务管理器截图。

## P0-R3 · 无头规则世界

问题：FarmState 及传递依赖能否脱离主场景运行？建立隔离入口，执行播种、时间推进、收获和存储，检查加载资源。对照普通规则入口的结果，测无人连接时的唤醒与内存。

通过条件：无 GPU/3D 场景依赖、规则结果一致、可保存恢复。失败时只拆真实资源依赖，暂不重写全部核心。产物为依赖图、可复现入口和资源结果。

## P0-R4 · 数据、身份与迁移

问题：v27 内容是否能完整映射到目标格式，身份和联系人如何跨设备持续？用隔离样本列明字段，试验 Windows→Mac→Windows、损坏包、未知版本、重复导入、密钥轮换和丢失恢复。

通过条件：已支持字段语义一致、原件未变、导入不重复发奖；身份恢复范围准确。没有某平台时标部分完成，不能把序列化单测当跨平台验收。产物为映射与兼容表，进入 M0 采用。

## P0-R5 · 端侧推理与云端预算

问题：小模型是否适合陪伴型游戏？选择一个可合法试验的中文模型与规则基线，在 M4/M4 Pro、Windows 可用样机测短对话、意图选择、摘要和取消；记录权重、量化、上下文、线程及后端。云端仅在具备授权与预算时试验，未授权部分使用替身验证预算逻辑。

通过条件：任务质量、资源、取消、卸载与深度休眠同时满足拟定预算，关闭后基本游戏正常。失败采用规则居民和可选云端，不强行常驻。产物为模型与框架分离的评估表，不把某模型可加载视为选型完成。

## P0-R6 · 原子交易与恢复

问题：两个并发买家、断线重试及进程中断会否造成双花？用两账户、一商品和唯一命令 ID 的隔离实验，对比候选事务存储与快照/日志方案；在提交前、中、后中断并恢复。

通过条件：库存非负、资金守恒、每命令唯一结果、备份能恢复同一提交点。失败缩小到已证明的单写入者事务边界，不用更多重试掩盖错误。产物为 ADR-003 决定和恢复证据。

## P0 出口判定

每项原型至少有实际结果与采用/回退决定，阻塞 M0 的数据与权威边界须完成验证；较后期 AI 原型缺设备可记录明确延后与规则回退，不能同时把它标为通过。P0 文档交付与 P0 全阶段完成分别记录。首轮工作安排见[工作包](../milestones/P0/WORK-PACKAGES.md)。
