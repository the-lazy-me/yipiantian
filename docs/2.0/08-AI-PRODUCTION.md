# 全流程 Vibe Coding 研发行动手册

状态：本规划的执行方法；工程操作遵循[AGENTS](../../AGENTS.md)与[Git 规则](../../rules/git-workflow.md)，不改变既有权限。

## 从需求到可验证结果

每个工作包明确用户体验、输入资料、修改范围、产物、验收场景与失败后的处理。AI 可以承担机制、艺术、3D、声音、编码与自动测试，但阶段完成依赖产物和证据，不能由生成者的一句“已完成”代替。

先读取项目上下文和相关规则，再读世界宪章、受影响规格与当前阶段计划。避免每次加载所有历史文件；发现冲突时回到权威来源修订。当前项目由主代理独立执行，不因本手册包含不同职责而自动启动并行代理。

## 六类生产闭环

| 工作 | 输入 | 可交付产物 | 验证重点 |
|---|---|---|---|
| 机制 | 宪章、系统接口、玩家场景 | 有输入输出的规则、实验参数与取舍 | 无强制人生路线，资源因果可核对 |
| 艺术 | 固定 v1 参考、结构与镜头职责 | 可评审单体/场景方案及实际生成记录 | 形体、笔触、完整轮廓与风格一致 |
| 3D | 已检查概念、尺寸与用途 | 可编辑源、导出资源、必要元数据 | 接地、连接、材质、动画与 LOD |
| 声音 | 行为语义、氛围与播放策略 | 源音、处理工程、游戏音频 | 授权、削波、循环、实际听感 |
| 编码 | 当前调用链、接口与验收 | 最小完整实现及必要回归 | 状态归属、错误语义、资源释放 |
| 自动测试 | 不变量、真实风险与构建版本 | 定向测试、模拟数据和报告 | 能发现对应错误，结果可复现 |

机制先用表格或无图形模拟检验因果，再进入表现；艺术先做代表样本再批量；代码按一条完整行为切片落地，不横向铺开大量空接口。生成资产失败时针对结构或材质问题修改，不连续生成不同风格碰运气。

## 一个工作包的执行方式

以“跨平台导入 v27”为例：输入为固定源码与脱敏样本，范围是格式转换和导入入口，产物是转换映射、隔离转换器、导入报告及往返夹具。先确认当前 v27 字段，再设计目标版本，写最小转换，检查失败不覆盖原件，在 Windows/Mac 验证语义状态，最后提交包含证据索引的完整切片。

任务卡要给出可观察结果，例如“损坏包导入后原世界仍可打开”，而非仅“完善存档系统”。验证命令只能引用真实存在的入口；尚未实现的验证步骤写预期过程，不伪造脚本名或通过数量。

## 自动化与独立审查

AI 可以生成测试输入、检查不变量、分析日志和对比画面。关键资产、账本和迁移测试用可控时间、固定种子与隔离目录；不修改真实存档或系统时钟。代码审查与测试结果分别记录，失败必须修复或明确阻塞相关阶段。

独立审查指采用另一轮基于验收标准的检查，不要求自动派生子代理。视觉、声音、乐趣与舒适度需要实际感知；自动像素比较只能发现变化，不能代替风格判断。测试模型不能把另一个模型的结论直接当证据。

## Git 与交付

修改前查看分支、上游、工作区与已有改动，按仓库流程安全同步。只暂存明确属于任务的路径；提交前核对差异、敏感数据、作者身份和验证范围。完整切片提交后同步当前上游，报告实际提交与同步状态。普通提交不等同发布；发布包、部署和对外传播保持各自授权边界。

探索放 `.local/`，采用的正式源与必要重建信息迁入受版本管理目录。文档只改权威页及受影响引用；历史实验不覆盖。模型、工具或供应商升级时只复核受影响能力和许可，不以“最新版本”为采用理由。

## 完成证据

每项实现记录提交、规则/数据版本、运行环境、执行步骤、结果、失败与未覆盖范围。机制实验保存种子和参数，资产保存源与实机对照，性能报告保存配对基线和条件。文档任务按 L0 检查链接、结构和一致性，不启动无关游戏或重复跑历史全量测试。
