# M0 · 规则核心与数据契约

状态：计划中，未验收。前置：P0 方向与关键可行性裁决；授权未明部分限制在调查和隔离实验。

## 阶段成果

建立同一农场规则的无场景执行入口，定义 2.0 数据与 v27 一次性导入边界。

权威规格：[相关设计](../../05-DATA-AND-NETWORK.md)；统一证据标准：[质量门槛](../../09-QUALITY-GATES.md)。本页只维护实施范围与顺序。

## 实施步骤与工作包

### M0-01 · 记录行为与数据基线

实施：梳理播种、浇水、收获、库存、布局、邻居和装饰的真实调用链；从当前代码生成隔离 v27 样本，记录字段和时间语义。

交付与验收：一份字段映射与正常/损坏/边界夹具；历史玩法文档与当前实现差异均可解释。

### M0-02 · 抽离第一条命令链

实施：选收获作为完整切片，沿用 FarmState；让 UI 发送命令、规则修改状态、存储提交结果，再迁移播种与浇水。

交付与验收：同一批次重复命令只产生一份收成；无场景入口与现有 UI 结果等价。

### M0-03 · 定义标识和序列化

实施：固定世界/农场/玩家/设备职责、时间单位、金额表示和版本协商；实现目标快照校验与隔离转换。

交付与验收：合法包可重新读取；较新或损坏版本拒绝且原件字节不变。

### M0-04 · 建立有限迁移与重放

实施：按已核对字段转换 v27，保留原件，记录无法转换字段；固定种子、事件顺序和舍入规则。

交付与验收：转换后地块、库存、邻居、布局与装饰逐项核对；重复导入不叠加。

### M0-05 · 接入双平台规则验证

实施：复用现有定向测试入口，在 Windows/macOS 执行相同规则夹具；必要时增加最小 CI 任务。

交付与验收：两个平台输出语义相同；失败样本能复现差异，当前 UI 基本种收无回归。

## 集成验收

Q1/Q2；检查存档写入中断、旧快照覆盖和重复恢复。跨平台完整安装包留 M1。

## 回退与边界

每次替换一条调用链；失败退回上一条已验证链路。迁移只写新目录，旧 v27 原件保留。

不全面改写 main.gd，不承诺所有历史存档，不引入经济或账号服务。

执行顺序、优先级与证据格式遵循[里程碑通用约定](../README.md)；本阶段尚无实际验收记录。
