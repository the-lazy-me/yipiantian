# ADR-009 · 温和模式的灾害与预警

- 状态：采纳（2026-11-15）
- 关联：[M6-03](../milestones/M6/RECORD-03-disasters.md)、[自然系统](../systems/nature.md)、[ADR-007](ADR-007-nature-time.md)、[ADR-008](ADR-008-rain-moisture.md)、[农场模拟规则](../../../rules/farm-simulation.md)

## 背景

M6-03 要求为灾害建立预警、影响范围、保护与恢复路径，同时守住一条产品边界：温和模式下不毁基本生活，风险农业才承担损失。当前自然状态只有天气种类，湿度由 ADR-008 的块边界规则结算；没有任何灾害来源、灾害存档或恢复机制。

约束有三条：

- **读档不重抽。** 灾害必须和天气一样由持久种子推导，不能因为进程重启而改变已公布的事件（ADR-007 决定 3）。
- **不扩持久形状。** `nature.json` 只有 `{seed, rules_version}`；农场文档的键数、格子形状与 `V27Importer.KNOWN_FARM_KEYS` 各自耦合，灾害不应把它们同时拖进迁移。
- **温和模式是默认且唯一的模式。** 风险模式需要玩家明确选择并在播种前展示可能损失；在 M6 阶段加入一个仅靠存档键切换的模式，会让同一份世界在不同客户端上得到不同的结算，代价远大于本切片的收益。

## 决定

1. **灾害是种子的纯派生层，不新增持久字段。** `NatureState.disaster_at(utc)` 由种子和 6 小时块序号推导，事件起止对齐既有天气块边界。因此推进分段点不变，`advance_to()` 不需要新增分段逻辑。
2. **只有干旱与暴雨两种。** 每种持续一个 6 小时块，强度只用于展示和排序，不派生出第二套倍率。同一 5 天内不会出现两次灾害，相邻事件实测至少相隔 5.25 天；世界没有持久化开始时间，因此不承诺“新世界先正常几天”——温和模式下的灾害只让生长变慢，早期出现也不会毁坏任何资产。
3. **灾害只改变已有湿度。** 完成的块在天气增量之上叠加热害：干旱额外 −1/8，暴雨额外 +1/4，结果仍限制在 0–1。生长仍只走 `weather_growth_factor(kind, moisture)`，成熟作物继续封顶，因此温和模式不会毁坏作物、产量、仓库、住宅或成熟批次。玩家已有的浇水（把该格湿度置 1）就是直接的当地保护手段；事件结束后天气规则自然恢复，不需要维修任务。
4. **规则版本升到 2，旧种子不静默改历史。** 天气推导函数不变；`rules_version=1` 的自然文档仍然可以读出并使用，并在下一次保存时写成 2。已经结算过的农场状态不会被重算，只有此后的结算才包含灾害层。更新的版本号仍然拒绝。
5. **预警与影响范围进入只读视图。** 权威摘要的自然视图增加 `disaster`（当前，含种类、起止、强度）与 `warning`（下一个块内开始，另含 `lead_seconds`）。影响范围在本切片是整个世界（区域级），不编造按地块细分的灾害地图。
6. **风险模式与灾害种类扩展不在本裁决内。** 未来若加入冒险农业，需要新的存档键、双向展示和双方一致的结算契约，另行裁决。

## 为什么不是另一侧

- **不把灾害做成存档里的事件表**：事件表会随世界寿命增长，还要处理裁剪、读档重放与两个客户端的写入竞争；种子推导没有这些成本。
- **不直接清空或销毁成熟产出**：温和模式承诺不毁基本生活，且“灾害先改变环境，再经农业规则影响生产”（自然系统设计）。销毁产出会绕过湿度规则，成为第二个损失来源。
- **不在本切片加入按地块的灾害范围**：没有可见的灾害地图与玩家可读的边界时，地块级范围只会制造不可解释的损失。

## 后果

- `NatureState` 多一个纯函数与两个视图辅助；`nature.json`、世界包 v3 信封、农场文档与 v27 键表都不变。
- 旧自然文档（`rules_version=1`）首次保存后升到 2；同一颗种子在升级前后的天气序列相同，只有未来结算多出灾害层。这一点必须写进记录，不能用“读档不重抽”掩盖规则升级的语义变化。
- 灾害没有独立的表现、声音或 NPC 反应；这些属于 M6-04 的表现切片，且只读消费本文的视图字段。
- 长期离线结算会跨过灾害块；因为灾后自动恢复，离线不会让世界停在灾害状态，也不会产生需要玩家点击的维修队列。
- 若后续要引入风险模式，需要同时修改本 ADR、ADR-007 的规则版本语义与自然系统设计，而不是只加一个布尔键。
