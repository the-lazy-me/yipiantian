# ADR-020 · 模型任务只产建议：单队列、懒加载与完全关闭

- 状态：采纳（2026-11-15），M9-02/M9-03 切片实现；真实后端、云路径与游戏接入待后续
- 关联：[M9 PLAN](../milestones/M9/PLAN.md)、[M9-02 协议记录](../milestones/M9/RECORD-02-protocol.md)、[M9-03 调度记录](../milestones/M9/RECORD-03-scheduler.md)、[NPC、商人与混合 AI](../06-AI-SYSTEM.md)、[模型候选与基准协议](../research/MODEL-CANDIDATES.md)

## 背景

M9-01 只核验了候选模型与推理库的许可，并给出尚未执行的 macOS 基准协议；没有下载权重、没有安装推理库、没有实测延迟或内存。[06-AI-SYSTEM](../06-AI-SYSTEM.md) 已经规定模型不承担世界规则的最终裁定，模型只能返回带状态版本和期限的结构化建议，执行前必须由规则层再次核对预算、权限、库存、距离或合同条件。

在这条边界进入任何真实模型之前，需要先固定四个契约：

1. 一个任务可以携带哪些可见信息、最多多长；
2. 一个响应怎样才算“可以形成建议”；
3. 过期、跨世界、跨状态版本和取消后的结果怎样被拒绝；
4. 模型何时加载、最多并发多少、闲置怎样卸载、完全关闭时怎样保证世界规则不受影响。

本裁决只覆盖 M9-02/M9-03 的协议与调度切片，不包含 M9-04 云端路径、M9-05 可靠性评估，也不把模型接入游戏运行路径。

## 决定

### 1. 模型只产建议，规则层是唯一裁定者

- `ModelTask.accept` 只返回 `suggestion`，不修改任务、世界或任何持久状态。建议的固定形状是：
  - `intent`：`{intent, confidence, reason, state_version}`；
  - `dialogue` / `summary`：`{text}`。
- 响应中的未知键不会进入建议。模型无法通过 `command`、`world_mutation` 等额外字段夹带动作。
- 建议必须通过四道门：结构合法 → 同一世界 → 同一状态版本 → 未取消且未过期。任何一道失败都返回 `ok=false`。
- 规则层在执行建议前仍要重新校验预算、权限、库存、距离、合同和当前状态版本；本协议不替代这些检查，也不把“模型说已经付款”当作账本事实。

### 2. 任务形状与可见上下文固定

- 任务类型固定为 `intent`、`dialogue`、`summary`；意图枚举固定为 `greet`、`trade`、`work`、`conflict`，对应基准协议的四类。
- 任务恰好九个字段：`id`、`type`、`world_id`、`state_version`、`visible_context`、`output_schema`、`created_utc`、`deadline_utc`、`cancel_id`。
- `visible_context` 只接受固定字段白名单（NPC/玩家标识、地点、话题、消息、附近、库存、价格、关系、近期事件、记忆、天气、时间），未知键拒绝；序列化上限 8192 字节、嵌套上限 8 层，只接受 JSON 兼容值。
- `output_schema` 对意图任务是非空枚举子集；对文本任务是 1..类型上限的 `max_tokens`。
- 输出上限按类型：`intent` 64、`dialogue` 120、`summary` 120。当前用 `ceil(UTF-8 bytes / 3)` 近似 token，是确定性边界，不是真实 tokenizer 计数。
- `create` 负责归一化：`created_utc` 默认注入的 `now_utc`，`cancel_id` 默认任务 `id`，`output_schema` 默认全枚举或类型上限；`valid` 只做无时钟的结构校验。

### 3. 迟到结果由取消与期限拒绝

- 每个存储任务都必须有非空 `cancel_id`；`cancelled_ids` 可以是 id 数组或 id 字典。
- 同一 `cancel_id` 取消后，迟到响应的结果是 `accepted=false, reason="cancelled"`；过期结果是 `reason="expired"`。
- 取消优先于过期：调用方已经明确撤回任务时，报告取消比报告过期更准确。
- 跨世界返回 `cross_world`，状态版本不一致返回 `state_version_mismatch`；意图响应还必须在自身 JSON 中携带与任务一致的 `state_version`。
- 本切片不实现跨进程或重启后的取消持久化；取消集合是调度器内存中的有界集合。

### 4. 单队列串行、懒加载与闲置卸载

- 同一时刻最多一个任务在跑；等待队列默认上限 8，超出返回 `queue_full`。队列上限只计等待任务，不含在跑任务。
- `submit` 不加载后端；任务第一次真正启动时才 `load()`。已加载后不再重复加载。
- 每个任务的期限来自 `deadline_utc`。在跑任务到期后标记 `timeout`，下一次 `poll` 才启动下一个；排队任务在启动前到期返回 `expired`，不调用 `generate`。
- 没有排队和在跑任务时，达到可注入的空闲阈值（默认 60 秒）调用 `unload()`；之后的新任务重新懒加载。
- 取消会移除匹配的排队任务并停止轮询在跑任务；取消本身不再触发 `generate`。后端已经开始的计算是否中止由真实后端负责，本切片不提供 abort。
- 调度器是显式时钟、轮询驱动的：`submit`/`poll`/`cancel`/`set_enabled`/`unload` 都接收 `now_utc`，不读取引擎时钟，测试可完全复现。

### 5. 完全关闭是硬边界

- `enabled=false` 时，`submit` 与 `poll` 立即返回 `disabled`，产生零次 `load`/`generate`。
- 关闭会清空队列、丢弃在跑状态、把被清任务的取消 id 记入有界集合，并在已加载时卸载后端。
- 调度器与世界规则之间没有依赖：关闭模型后，农场、经济、NPC 规则继续运行；测试用纯规则调用证明了这一点。模型不可用不是世界规则失败的条件。

### 6. 后端接口与失败语义

- 后端只需实现 `load()`、`generate(task)`、`unload()`、`loaded()`；`load` 返回布尔、字典或空（空视为成功），`generate` 返回完成、`pending` 或错误。
- 测试用进程内假后端，不引入真实模型、不联网、不创建线程。
- 加载失败时调度器调用 `unload()` 清理半加载状态，只让当前任务失败；后续任务会重新尝试加载。
- 后端错误只让当前任务失败。本切片没有自动重试、退避或重试预算；这些属于后续可靠性工作。

### 7. 默认数值是实验边界

```text
可见上下文        8192 字节、8 层
输出上限          intent 64 / dialogue 120 / summary 120 token 当量
等待队列          8
闲置卸载          60 秒
取消集合          256 条
```

这些数值来自当前实现需要和基准协议，不是实测结论。真实模型的内存、延迟、能耗与游戏帧时间尚未测量，不能据此宣称“可常驻”。

## 为什么不是另一侧

- **不为每位 NPC 常驻模型，也不先做并发**：M9-01 没有任何常驻内存、GPU 或帧时间数据；单队列串行与懒加载是当前唯一能被证伪的最小方案。
- **不在本切片接入真实后端**：权重与推理库许可仍需发行前复核，模型质量与性能未测；先固定协议与调度契约，再用假后端验证，避免把未验证的运行时行为混进规则测试。
- **不让模型直接执行动作**：模型输出是建议，不是账本或命令；直接执行会绕过规则层的预算、权限、库存与合同检查，并把提示注入放大为世界事实。
- **不接受任意上下文字典**：字段白名单、JSON 兼容值、深度与字节上限共同限制隐藏状态、超长提示和提示注入面。字段值是否真的可见仍由调用方负责。
- **不做无界取消历史**：取消集合有界并按插入顺序淘汰最旧 id；重启后的取消持久化留给会话/存档工作。
- **不用 tokenizer 精确计数**：当前没有固定模型与 tokenizer，字节近似是后端中立且可复现的边界；M9-01 选定模型后再替换为真实计数。
- **不做自动重试与云回退**：错误先只让当前任务失败，避免在预算、能耗和故障语义未定义时引入隐式放大；云授权、费用预留和硬预算属于 M9-04。
- **不把关闭实现成“忽略错误”**：关闭必须零加载、零生成、清队并卸载，才能在能效与隐私上给出可验证证据。

## 后果

- 新增 `Game/ai/model_task.gd` 与 `Game/ai/model_scheduler.gd`；新增两个无头夹具与三份文档。未修改农场、世界、场景、UI、工作流、规则或任何 `PLAN.md`。
- 模型建议不会自动进入游戏；后续接入仍需一个规则层适配器，重新校验并显式提交世界命令。
- 调度器不能中止已经开始的真实推理；接入真实后端时必须提供 abort 或忽略迟到结果的二次保护（协议已能拒绝迟到结果）。
- `queue_limit` 不含在跑任务；若未来要求“总并发资源上限”，需要新增总预算而不是复用该字段。
- 队列、取消集合和在跑状态不持久化；重启后只保留协议层的过期与版本拒绝。
- 默认 8/60/256/8192/64/120 都是实验边界，真实体验和 M4/Windows 数据可能要求调整。
- `Game/ai/*.gd.uid` 由 Godot 首次加载自动生成；没有新增存档字段或世界包字段。

## 复审触发条件

出现以下任一情况时重开本裁决：

- 接入真实 llama.cpp/MLX 或其他后端，需要定义线程、进程、abort、完成回调和加载失败重试；
- M9-04 云端路径需要授权、最小上下文、费用预留、实际用量与硬预算；
- M9-01/M9-05 产生实测内存、延迟、能耗或游戏帧时间，要求调整队列、闲置阈值或输出上限；
- 游戏需要同时运行多个模型任务，单队列成为可验证瓶颈；
- 固定模型与 tokenizer 后，字节近似不足以约束真实输出；
- 需要跨重启保留取消、队列或建议状态；
- Windows 实机或双平台 CI 暴露与 macOS 不同的加载/卸载行为。
