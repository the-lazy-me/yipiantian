# ADR-005 · 村落物资归属与赠送

状态：裁决已定（2026-11-15），实现按切片推进。影响 M5-02（赠送）、M5-03（偷菜）、M7（市场）。

## 问题

现在一个世界只有一份农场状态，`inventory` 是**所有人共用的一个仓库**。收成进入它，做饭、喂动物从它扣除。这带来两个后果：

- 赠送没有可转移的东西：从公共仓库“送”给别人，只是把左口袋的菜挪到右口袋。
- “我的收成”不存在，M5-03 的损失上限、M7 的买卖与 M8 的账本都没有归属对象。

要决定的是：在引入整村多地块之前，先把哪一层归属做实，既能让 M5-02 的原子赠送成立，又不把现有单人存档与全部农场规则推倒重来。

## 裁决

### 归属单位：每个玩家一个口袋（bag），土地仍暂时共享

- 权威为每个有 `player_id` 的成员维护一个口袋：`{player_id: {crop_id: int}}`。
- **收获计入动作执行者的口袋**，不再计入公共 `inventory`。无玩家身份（匿名成员、单人游戏、无头命令行）时仍记入 `inventory`，因此现有单人玩法、导入与所有既有测试的行为不变。
- 公共 `inventory` 保留为“世界的公共存量”，未来的公共工程与活动可以使用；它不是任何人的财产，赠送与交易不使用它。
- 土地、院落、装饰仍属于世界而不是个人。地块归属（地籍）留给 M11；M5-04 只做院内住宅，其材料从玩家口袋扣。

理由：口袋是最小可原子转移的归属单位。它不需要拆世界文档、不需要多地块渲染、不会让现有存档失效，却立刻让“赠送”“偷菜损失上限”“买卖”有明确对象。把土地也拆开需要同时改渲染、相机、命令与权限四处，属于 M5-04/M11 的工作，不阻塞 M5-02。

### 数据位置：跟随农场文档

- 口袋存进 `FarmState` 的文档（`bags`），与 `inventory`、`harvested` 同一个快照、同一次落盘。
- 一次命令的“扣发送方 + 入账接收方”在**同一个候选快照**里完成，由 `FarmStore` 一次写盘提交：不存在扣了没入账的中间状态。
- 命令幂等沿用现有事务账本：同一条赠送命令 id 重放返回原结果，不重复转移；失败（余额不足、收件人不存在、数量非法）不产生候选，不落盘。
- 未知/缺省的 `bags` 在恢复时视为空表；旧存档因此仍可读（早期阶段不承诺旧档兼容，但这里不需要额外迁移）。

### 赠送命令

```
{kind: "gift", id, to_id, crop_id, amount, at_utc}
```

- 发送方由权威按连接解析，**不接受命令里的 from 字段**：客户端不能替别人送礼。
- `amount` 必须是正整数且有上限（`GIFT_MAX`），`to_id` 必须是本世界里出现过、有合法 ID 的成员或历史玩家；不存在或非法时具名拒绝。
- 接收方离线也能收到（口袋按 ID 存，不要求在线），下次加入时摘要里就有。
- 赠送不推进农场时间，也不触发作物结算。

### 客户端

- 客户端重放同一条赠送：从自己的口袋扣除、给对端口袋加上；双方口袋都在本地快照里，重放是确定性的。
- HUD 在联机模式下显示**自己的口袋**（“我的收成”），不再显示公共 `inventory`；单人模式保持原样。
- 社交面板每个联系人加“送一份收成”，作物从自己口袋里有存货的种类中选，数量固定 1（先不做批量）。

## 未采纳

- **把 `inventory` 直接改成每个玩家一份**：会同时改动单人存档、厨房、动物、导入与世界包的全部现有契约，收益与上面的方案相同。
- **赠送走社交文档**：社交文档与农场文档是两次落盘，无法保证“扣了必入账”；赠送必须与物资同一次提交。
- **赠送写成“公共仓库转个人口袋”**：等于凭空生成财产，会被反复领取。

## 影响与风险

- 口袋会让“谁该得到收成”变得可见，但也意味着公共仓库不再自动增长；依赖公共库存的既有玩法（厨房、动物）在联机模式下仍被禁用，不产生分叉。
- 匿名成员没有口袋，也不能收礼：他们能干活，但收成进入公共仓库。这是已知的、可解释的边界。
- 赠送上限按作物计数（与 `MAX_HARVEST_COUNT` 同量级），不是按价值；引入市场价值后需要重新审视。
- 已有世界文档在加入 `bags` 后大小增加，摘要变大；当前世界约 17 KB，口袋数量随成员数线性增长，未做压缩。
