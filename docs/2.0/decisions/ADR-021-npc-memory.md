# ADR-021 · 居民记忆与人格：规则文档、容量与模型边界

- 状态：采纳（2026-11-15），M10-01 切片实现完成；真实 NPC、模型接入、多人同步与 Windows 实机验证待后续
- 关联：[M10-01 记录](../milestones/M10/RECORD-01-memory.md)、[M10 PLAN](../milestones/M10/PLAN.md)、[AI 系统](../06-AI-SYSTEM.md)

## 背景

M10 要求居民“在自己的资源和关系约束下生活”。在接入任何模型之前，必须先确定三件事：

1. 人格是否作为可重建的规则基线，而不是每次加载重新随机；
2. 经历保存在哪里、保存多少、满了如何淘汰、如何可重复地取回；
3. 模型能否写记忆、能否把建议当成事实。

如果记忆依赖模型内隐状态，存档无法审计、恢复可能漂移、不同世界会互相污染，也无法在模型停用时保留已提交经历。[AI 系统](../06-AI-SYSTEM.md) 已限定：事件、主观评价和临时对话分层，传闻不能变成账本事实，模型只获得可见信息。

本裁决只覆盖不依赖模型的 M10-01 切片：人格基线、有界情景记忆、确定性检索、严格恢复。

## 决定

### 1. 记忆是规则文档，不是模型内隐状态

- 新增 `Game/npc/npc_memory.gd`。整份文档是可序列化的纯数据，形状固定为 `schema`/`world_id`/`npcs`；每位居民有 `dropped` 与 `entries`。
- 每条记录固定八字段：`id`、`kind`、`participants`、`summary`、`salience`、`at_utc`、`world_id`、`state_version`。
- `kind` 只允许 `trade`、`gift`、`conflict`、`weather`、`dialogue`、`observation` 六种。新增类型必须同时更新规则、测试和本文档。
- 模块不读时钟、不落盘、不访问场景/网络、不调用模型；`now_utc` 由调用方显式注入。
- 本切片不新增农场顶层键，不修改农场存档格式，也不改变任何世界状态。

这样做的目的不是追求通用事件库，而是让“这个居民记得什么”成为可校验、可迁移、可删除的权威数据。M10-02 的主观评价、传闻来源和承诺可以在此文档之外分层，但不能反过来改写本切片的已提交事件。

### 2. 写入只来自已接受的规则事件

- 唯一写入入口是 `remember(document, npc_id, event, now_utc)`；它是修改传入文档的纯规则函数，返回 `{ok, reason, duplicate, size, dropped, evicted}`。
- 失败不落任何字段：未来 `at_utc`、跨世界记录、非法枚举/参与人/摘要/显著性、未知键、重复 id 全部返回机器原因，文档保持不变。
- id 在整个文档内唯一。同一 id 重写返回 `ok=false, reason="duplicate"`；同一事件内容换新 id 会存成两条，去重由调用方负责。
- 模型建议不得直接进入记忆。建议必须先由规则层核对预算、权限、库存、距离或合同，成为已接受的世界事件，再由事件调用方提交 `remember()`。因此“模型说发生过”不构成记忆，更不构成账本事实。

### 3. 容量与淘汰

```text
每位居民 64 条
淘汰顺序：最低 salience → 最旧 at_utc → id 升序
dropped：每条淘汰 +1，单调不减
```

- 容量按居民隔离，一个居民满员不影响其他居民。
- “低显著性 + 最旧”优先淘汰，保留高显著性近期事件；低显著性的新事件也可能被立即淘汰，这是容量规则的直接结果，不做特殊加权。
- `dropped` 是单调证据，不是可回收配额；JSON 往返和多次写入都不会把它重置。
- 没有删除 API。删除私人对话或隐私导出属于后续权限切片，必须走显式规则，不能由模型触发。

### 4. 确定性检索与只读衰减

- `retrieve(document, npc_id, options)` 要求 `options.now_utc`，可选 `limit`（1..64，默认 8）、`participant`、`kind`。
- 排序键：`max(1, salience - floor(age_days))` 降序 → `at_utc` 降序 → id 升序。整数运算和 id 平局保证跨平台确定性。
- 衰减只用于排序，不改写原始记录的 `salience`/`at_utc`；本次实现不引入 `decay_utc` 参数，也不做后台压缩。
- 返回的是记录副本，调用方修改结果不会污染文档。
- `at_utc > now_utc` 在写入和恢复时都拒绝；检索前会先校验整份文档，因此时钟回退不会被静默解释成“零年龄”。

选择“只影响检索排序”而不是“写回衰减后的显著性”，是为了让原始证据保持不变、同一存档在任意时刻恢复后仍能得到相同事实；排序可随 `now_utc` 变化，但记录不会因读取而漂移。

### 5. 严格恢复与有限旧档默认

- `from_document()` / `from_json()` 先读取，再以 `validate_document()` 做一次严格校验；任一步失败都返回 `{ok:false, reason}` 和空文档。
- 拒绝：未知键（文档/居民行/记录三层）、缺必需字段、错误类型、越界值、非法 id、重复 id、跨世界记录、未来时间、负 `dropped`/`state_version`、超过 64 条的居民行、非 1 的 schema。
- 旧档只对以下字段给固定默认：`schema=1`、`npcs={}`、`dropped=0`、`entries={}`、记录 `world_id=文档 world_id`、`state_version=0`、`participants=[]`。`id`/`kind`/`summary`/`salience`/`at_utc` 始终必需。
- JSON 解析后的整数计数器归一化为 `int`，`at_utc` 归一化为 `float`。
- 验证需要 `now_utc`，因为“未来时间”不是文档自身的属性。

### 6. 人格是可重建的规则基线

- 新增 `Game/npc/npc_personality.gd`。五个固定维度：`diligence`、`warmth`、`suspicion`、`curiosity`、`generosity`，取值 0..100 整数。
- 由 `npc_id` 与 `world_seed` 经 FNV-1a（UTF-8 字节、每步 32 位掩码）派生，输入包含固定版本前缀、种子、id、维度名和索引；不使用 RNG，也不持久化派生结果。
- 同一 id/seed 永远相同；不同世界种子或不同 id 可以不同。`valid()` 严格检查恰好五个已知维度；`describe()` 只输出确定性中文短句，供展示，不参与规则解析。
- 人格只作为规则层权重和展示，不授予资源、权限或叙述事实；林婶、许伯、阿舟的既有身份不能用随机派生覆盖。后续把已知设定接入时，应显式覆盖或校准，而不是改动散列输入来“碰巧”得到目标值。

### 7. 与模型建议的边界

- 模型可读取 `retrieve()` 的可见上下文，但不可写记忆；模型调用清单中不新增任何记忆写入动作。
- 模型建议的结构化意图、理由、依据的状态版本和有效期仍由规则层复核；过期或越权建议丢弃。
- 记忆中的事件不自动成为可交易资产、权属或账本余额；这些仍由既有账本、市场和合同规则裁定。
- 模型停用、断网或预算耗尽时，记忆文档保持可用；居民按规则继续生活。

### 8. 不改存档形状与网络

- 本切片不把记忆接入 `FarmState` 快照、世界迁移或网络消息；字段与调用点留给后续接线。
- 因此本切片没有引入跨世界迟到响应、多人私有内容过滤或同步冲突问题；这些在接线时必须重新裁决。

## 后果

- 记忆规模有硬上限：每居民 64 条，整份文档的规模随居民数线性增长，检索与校验都是小规模有界操作。
- 每次 `remember()` / `retrieve()` 都会校验整份文档，写入成本为 O(居民数 × 64)；当前 3 位样本居民下可接受。若未来居民数显著增大，应把校验拆到加载边界，而不是放宽字段检查。
- 文档级 id 唯一使跨居民迁移记录需要新的 id；调用方不能把同一事件 id 复制给两个居民。
- 没有删除和压缩 API；M10-02 的“按重要性压缩、删除不再必要的原始对话”需要在此基础上新增显式规则，不能由模型直接改文档。
- 人格散列是版本化输入的一部分；若未来调整派生公式，必须同时声明旧世界的兼容策略，避免同一居民在升级后性格漂移。

## 未覆盖
