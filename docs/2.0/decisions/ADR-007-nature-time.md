# ADR-007 · 自然状态独立文档与固定时间语义

- 状态：采纳（2026-11-15）
- 关联：[M6-01](../milestones/M6/RECORD-01-nature-time.md)、[自然系统](../systems/nature.md)、[农场模拟规则](../../../rules/farm-simulation.md)

## 背景

M6-01 要求天气由固定种子与时间轴推导，读档不重抽，同一事件在各模式一致。天气种子需要持久化，但农场文档有精确键数校验，`V27Importer.KNOWN_FARM_KEYS` 与格子形状又各自耦合；过去新增农场键时曾漏改第三处。世界包和 v27 导入仍以农场文档为权威，贸然扩键会把一次小切片扩散到格式与迁移。

同时，“现实昼夜、农业时间、季节”需要一个唯一权威，否则容易产生三套时钟或引入系统时区、真实地理位置依赖。

## 决定

1. **UTC 时间点是唯一权威。** 昼夜、农业时间与季节都是对同一时间点的解释，不保存第二套时钟。
2. **自然状态放独立文档 `nature.json`。** 只保存 `{seed, rules_version}`；天气事件由种子与块序号的固定散列推导，不逐条存盘。独立存储避免农场文档键数、v27 导入键表和世界包键集同时变化。
3. **缺失文档不重抽。** 旧存档没有自然文档时使用固定默认种子，并在下一次保存时写盘。存在但损坏或版本较新的文档拒绝加载，不静默换种子。
4. **规则版本随种子保存。** 事件推导算法变化时拒绝旧规则版本，而不是用同一颗种子重算出另一段历史；是否提供旧算法由后续迁移需求决定。
5. **实验参数先固定、不承诺最终数值。** 6 小时天气块、7 天季节、06:00–18:00 UTC 昼夜窗口都是 M6 实验值；M6-02/M6-03 可以在不改变本 ADR 结构的前提下调整。真实天气、地理位置和系统时区不进入必要输入。

## 后果

- `FarmState` 与 `V27Importer.KNOWN_FARM_KEYS` 不需要为种子改键。世界包已升到 v3 并在信封携带 `nature`：导出读取真实种子，v1/v2 旧包与 v27 导入使用固定默认种子。代价是每个携带世界的边界都必须显式处理这个独立文档，不能假设农场文档已包含它。
- 天气历史不是一张事实表，而是“种子 + 时间点 + 规则版本”的函数；只要规则版本不变，读档和任何推进路径得到同一事件。规则升级需要迁移策略时另行裁决。
- 共享世界权威与无头运行器（离线结算入口）读取同一份种子；单机场景目前仍只经 `FarmStore` 存取农场，不读自然文档，本次也没有展示自然视图。
- M6-02 的区域降雨／湿度应建立在 `weather_at()` 的事件区间上，不另建随机源。
