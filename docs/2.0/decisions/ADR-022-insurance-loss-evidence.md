# ADR-022 · 保险的损失证据与唯一赔付

- 状态：P0-A 运输损失证据已实现（2026-11-15，见 [M8-03a](../milestones/M8/RECORD-03a-transport-loss.md)）；M8-03 保单、保费、理赔与风险信息定价仍阻塞——固定保费仍会被“只保即将受灾对象”套利，P0-B 风险模式作物损失也未做。
- 关联：[M8-03 调查记录](../milestones/M8/RECORD-03-insurance.md)、[M8 PLAN](../milestones/M8/PLAN.md)、[经济与金融](../systems/economy-finance.md)、[自然系统](../systems/nature.md)、[ADR-009](ADR-009-disasters.md)、[ADR-013](ADR-013-limited-logistics.md)、[ADR-014](ADR-014-double-entry-ledger.md)、[ADR-017](ADR-017-bank-loans.md)

## 背景

M8-03 要求“承保、保费、免赔、限额、损失证据与唯一赔付”，并验收两条规则：已发生的灾害不能追溯投保；同一损失不重复理赔。

这两条规则的共同前提不是保单表，而是**权威损失事件**：世界必须先能回答“谁、何时、因何、损失了什么、多少价值”，并且这个回答不是玩家自己提交的。当前实现没有这样的记录。ADR-009 明确规定温和灾害只改变湿度，成熟作物继续封顶；ADR-013 明确规定在途货物只有 `in_transit`/`delivered`，没有丢失、损坏或风险路线；ADR-014/017 的准备金报告仍把 `claims` 固定为 0。

因此本裁决先回答“现有系统有没有可信损失来源”，再决定 M8-03 是否可以实现，以及如果以后实现，保单、理赔和账本应采用什么边界。

## 结论

**当前没有可用的保险损失证据，M8-03 阻塞。** 逐条判定见[调查记录](../milestones/M8/RECORD-03-insurance.md)：

| 价值减少路径 | 当前是否发生 | 是否有耐久逐笔损失行 | 能否作为保险损失 |
|---|---|---|---|
| 作物被毁或减产 | 否。灾害只改湿度，作物延迟成熟，收获固定 1 篮 | 否 | 否 |
| 在途货物丢失/损坏 | 否。只有 `in_transit`/`delivered` 两个终态 | 否 | 否 |
| 盗窃 | 是。货物从所有者格子转移到小偷口袋 | 否。只有每所有者每日 `lost` 聚合计数和每小偷最近时间戳 | 否 |
| 贷款逾期坏账 | 只把合同置 `overdue`，不核销、不扣押 | 否 | 否 |
| 成交/运费销毁 | 是。真实销毁并有耐久分录 | 分录是服务成本证据，不是意外损失 | 否 |
| 厨房/动物消耗、赠送、出售、拆除 | 是，但均由玩家自愿操作 | 无独立损失行 | 否 |
| 市场价格变化 | 无事件，也没有库存减值 | 否 | 否 |

即使以后补上损失行，还有第二个阻塞点：**当前自然事件由持久种子确定性派生，客户端也能拿到种子并推导未来灾害**。`NatureState.disaster_at()` 与 `next_disaster_at()` 是纯函数，单机读取 `nature.json`，共享世界摘要也携带种子并在摘要过期后本地推导。只要损失结果可由客户端状态推导，固定保费的可选保险就会出现“只给即将受灾的对象投保”的套利；这不是理赔表能修复的问题，必须先决定风险信息与定价语义（强制/合作保险、按已知日程定价、或让风险不可由客户端推导）。

## 现有路径的判定依据

1. **作物被毁/减产不存在。** `FarmState._settle_cell_environment()` 对每个完成的 6 小时块只调整 `moisture`；`weather_growth_factor()` 的注释明确“作物只会更晚成熟，收获上限和 1 篮产量不变”；`_moisture_after_disaster()` 只返回湿度。`_act()` 的 `harvest` 固定 `reward_amount = 1`，没有数量或品质字段。当前没有“减产”可以表达的值。
   - 若要把“减产”作为损失，必须新增产量/品质或成熟状态规则；温和模式下销毁成熟产出还会直接违反 ADR-009 决策 3 与“不直接清空或销毁成熟产出”的拒绝理由。
2. **在途丢失不存在。** `Market.ship()` 扣货、扣运费并写 `in_transit` 行；`Market.deliver()` 在到达时把数量加回口袋并写 `delivery_<sequence>`。`SHIPMENT_STATUSES` 只有两个值，ADR-013 明确不提供丢失、损坏、拒收、中途取消或退款。
3. **盗窃只留下聚合记录。** `_act()` 的成功盗窃会清空格子、把 1 篮作物放进小偷口袋、递增世界 `harvested`，并写 `_theft_record()`：`{enabled, day, lost, last}`。`lost` 是同一所有者当天最多 3 次的聚合计数；`last[actor]` 只保存每个小偷最近一次时间戳；下一个 UTC 日首次发生盗窃时 `lost` 和 `last` 整体重置（不是日界线自动清空）。没有 `loss_id`、货物种类、格子、数量行或逐笔时间。
   - 命令层的 `command_results` 只有 64 条，且结果记录不含格子、也不标记“这是盗窃还是授权收获”；它不能替代耐久损失行。
   - 盗窃是转移而不是价值销毁：作物仍在小偷口袋里。赔付会从保险基金向被偷者转移现金，但没有对应的世界价值消失。
   - 盗窃还是所有者主动开启的（`set_theft`），可以被自导自演或小号放大。当前玩家 ID 只按安装标识，不能证明“小偷不是本人或关联方”。
4. **逾期坏账没有实现损失。** `Loans.settle()` 只把 `open` 改成 `overdue`，不写分录、不追加费用、不核销，`outstanding_principal()` 仍把逾期合同算作银行资产。没有“损失已实现”的时点，保险无法区分“会还”和“不会还”。
5. **费用销毁是自愿服务成本。** 成交费和运费确有耐久分录（`trade`、`shipping_fee`），但它们是玩家为成交/运输主动支付的费用，不是意外损失。承保费用会形成“付保费换回手续费”的套利，且交易/物流分录有界、可被淘汰。
6. **其他减少都不是损失。** 厨房、动物、赠礼、篮子、下单托管、出售和拆除都是玩家主动使用或转移资产；价格变化没有事件，也没有库存减值；仓库、住宅和动物没有耐久损耗或死亡规则。

## 选项

### A. 保持阻塞，不实现 M8-03

保持 ADR-009/013 的既有承诺，不制造第二套损失来源。代价是 M8-03 无法验收。这是当前唯一不需要修改产品边界的选择。

### B. 温和灾害直接造成作物减产（任务示例的形状）

在干旱/暴雨块完成时，对未浇水、未收获的地块生成一次确定性减产损失行。它需要先决定“减产”在 1 篮、无品质模型里的含义：

- 成熟作物直接损失，收获 1 → 0；或
- 增加 `damaged` 状态，要求重新生长一段时间；或
- 新增品质/数量字段，按比例减产。

**冲突点：**

- ADR-009 决策 3 明确“温和模式不会毁坏作物、产量、仓库、住宅或成熟批次”；拒绝理由明确“不直接清空或销毁成熟产出”。本选项必须修改 ADR-009，而不是在保险实现里悄悄新增。
- `docs/2.0/systems/nature.md` 承诺温和模式“成熟成果与基本住所受保护”，并把风险农业限定为需要主动选择的模式。默认摧毁作物会破坏这条产品边界。
- “未浇水才损失”会把浇水变成每天必须的操作，与自然系统“任何一种应对都不应成为每天必须操作的作业”相冲突；而且玩家可以通过浇水完全规避，损失证据的分布会变成“谁忘了浇水谁被赔付”，不是可承保的自然风险。
- 只有六种商品有 `EconomyCatalog.base_price`；其他作物没有市场价格，保险金额没有权威来源。
- 长离线结算会跨过大量灾害块，损失行可能按“每块 × 每格”增长，需要额外的聚合、上限和归档规则。

**判定：** 不建议在没有明确产品修订的情况下采用。

### C. 风险模式下的作物损失

新增世界级“风险模式”（与 ADR-009 决策 6 要求的独立裁决一致），只有主动进入风险范围的地块/作物在灾害时生成损失行；温和模式继续只改湿度。

**优点：** 保留温和模式承诺；风险范围可以在播种前展示；与自然系统“风险农业需主动选择”一致。
**代价：** 需要新的世界级规则与存档键、在线/离线一致结算、客户端双向展示、风险同意和退出规则；仍然需要减产模型和价格来源；仍然受“种子可推导未来灾害”的套利问题约束。
**判定：** 如果产品要的是灾害/农业保险，这是比 B 更干净的路径，但不是最小切片。

### D. 风险运输与在途损失（推荐作为首个证据来源）

现有 shipment 行已经耐久保存 `id/owner/good/quantity/origin/destination/fee/depart_utc/arrive_utc/status`，货物在发货时已从口袋移入在途，交付是权威确定性扫描。再增加一个显式风险声明和 `lost` 终态：

```text
shipment = 现有字段 + {
  risk: "safe" | "declared",     # 发货时显式声明并展示最大损失
  status: "in_transit" | "delivered" | "lost",
  lost_utc: 0.0,
  loss_id: ""
}
```

- 默认和平路线保持 `safe`，永远交付；只有 `declared` 的发货在到达扫描时按权威规则判定 `lost`。
- `lost` 是终态：货物不回到口袋，`delivery_id` 为空，`loss_id` 指向唯一损失行；重复扫描是 no-op。
- 损失价值按发货时锁定的商品参考价和数量计算，不读取损失后的市场价格。
- 通关/风险声明与最大损失在发货前可见；这与产品设计“运输承担事先声明的风险”和“保险只赔付已登记的受保损失”一致。

**冲突点：** ADR-013 当前明确排除风险路线、丢失和保险；本选项必须重开 ADR-013，并更新经济与金融系统中的“和平区域默认保护基本交付；风险路线须显式同意”。ADR-009 不受影响。
**判定：** 推荐。它不需要摧毁温和模式的作物，已有耐久 shipment 行和明确的数量/价值，最容易形成可信的“已登记损失”。

### E. 把盗窃事件补成逐笔损失行

在 `_theft_record()` 之外增加有界的逐笔行（`thief`、`owner`、`crop`、`cell`、`at_utc`、`loss_id`），让盗窃可追溯。

**判定：** 可以作为社会/执法证据，但**不应作为保险损失**。盗窃仍是转移而非销毁，且所有者主动开启、玩家身份可被小号伪造；只补行不能解决套利。若未来要把盗窃变成不可自导自演的风险，需要先改盗窃规则和身份模型。

### F. 贷款坏账或费用保险

**判定：** 均不采用。逾期不是已实现损失，承保贷款会让借款人从违约中获益；费用保险只是把自愿成本退还给投保人，形成无风险套利。

## 建议的最小前置切片 P0（本次不实现）

P0 只做“权威损失事件原语 + 一个真实损失来源”，**不做保单、保费、理赔或保险现金**。两种来源二选一，推荐先做运输损失：

### P0-A（推荐）：运输风险损失

```text
economy.losses = {
  sequence: int,
  events: {loss_id: event},
  archived: int
}

event = {
  id, sequence, kind, at_utc, cause_start_utc, cause_end_utc,
  victim, shipment_id, good, quantity, unit_value, value, rule_version
}
```

- `kind = "transport_loss"`；`id = "loss_" + sequence`；`dedup_key = kind + cause_start_utc + victim + shipment_id`。
- 由 `Market.deliver()` 的权威扫描在到达时生成；与 `status = "lost"`、`lost_utc`、`loss_id`、货物 `lost` 计数写入同一候选快照，任一步失败整次丢弃。
- 发货时锁定 `unit_value`（使用 `EconomyCatalog` 的参考价；未定价商品不进入保险范围）和 `quantity`，损失不接受玩家自报金额。
- `cause_start_utc/cause_end_utc` 是风险窗口的实际起止，不是结算扫描时刻；这样离线补算也能证明损失发生在哪一段。
- 损失行有界保存；在 P0 没有理赔时，只保留终态证据和归档计数。接入 P1 后，每条损失必须在同一候选内绑定唯一 claim，或明确标记为不承保，不能让损失行先被淘汰而无法理赔。

**守恒与存档影响：**

- 现金在损失时不变；发货时已扣的运费仍按 ADR-013 销毁。货物守恒等式增加 `lost` 终点：`袋子 + 商人库存 + 卖单预留 + 在途 + 已消耗 + lost == 产出 + 商人授予`。
- 农场格式仍为 27，不新增农场顶层键；新键只进入 `economy`（`losses`）。`Economy.STATE_KEYS` 需要增加键并明确旧文档缺键时的空形状恢复，不能把缺失键当成自动迁移。
- `Market.valid` 需要扩展 shipment 状态与 `lost_utc/loss_id/delivery_id` 的互斥校验；旧 shipment 只有两态，按原样读入。
- 长时间离线补算可能一次生成多条损失；需要一个确定的排序（shipment `sequence`）和上限/归档策略。

### P0-B（仅当产品明确要灾害作物保险）：风险模式作物损失

不修改温和模式，新增风险模式后：

```text
event.kind = "crop_loss"
event += {field_id, cell_id, crop_id, stage, quantity_before}
```

- 只在已进入风险范围的地块、灾害块完成时生成；每个 `(cause_block, field_id, cell_id)` 最多一条。
- 损失时点用块起止表示；结算补算时不能把扫描时刻当损失时间。
- 需要先决定减产模型（清空/受损状态/品质数量）和价格来源；只有 `EconomyCatalog` 已定价的六种商品可保。
- `FarmState._valid_snapshot()`、`valid_cell_snapshot()` 和 `V27Importer.KNOWN_FARM_KEYS` 的形状影响取决于是否给 cell 增加状态；如果只清空 cell 并把证据放进 `economy.losses`，农场顶层键可保持不变。
- 必须同时修订 ADR-009，明确“温和模式仍不产生损失，风险模式才产生”。

## 条件性的保单与理赔设计（P0 完成且产品决定风险定价后才可采纳）

以下只是设计草案，不是当前可实施规格。

### 资金与科目

- 新增独立的 `insurance` 现金持有科目（类似 `bank`，不是玩家账户），不把保费混入 `bank`。否则 ADR-017 的 `bank.cash == capital - outstanding + fees` 精确定式会被破坏。
- `insurance.cash` 计入 `total_cash` 与逐科目对账；`issued` 不因保费或赔付改变。
- 新分录：
  - `insurance_premium`：借 `insurance`，贷 `account:<owner>`；
  - `insurance_payout`：借 `account:<owner>`，贷 `insurance`。
- 保费是转移，不是销毁；赔付是转移，不是发行。准备金不足时不能凭空发行补偿。

### 保单

```text
policy = {
  id, owner, product, subject_type, subject_id, coverage_limit,
  deductible, premium, effective_utc, expires_utc, status,
  remaining_coverage, exclusions, rule_version
}
```

- `product` 首版只允许 `transport_loss`（P0-A）或 `crop_loss`（P0-B）；`subject_type` 对应 `shipment` 或 `cell`。
- `exclusions` 是产品规则固定的除外列表（费用、盗窃、价格变化、故意行为等），报价时展示并随保单持久化，不能由玩家在索赔时修改。
- 报价在签约前返回保费、免赔、限额、生效/到期、除外事件和赔付资金来源；签约时一次性从所有者账户扣保费。赔付资金来源只限保险现金与已收保费，不承诺凭空发行。
- 同一 `owner + subject_id` 同时最多一份有效保单；重叠保单拒绝。
- 运输保单必须在发货前绑定 `shipment_id`；作物保单必须在 `cause_start_utc` 之前生效。
- 保费不退；保单取消不改变已发生损失的理赔资格，也不退还已付保费。

### 理赔

```text
claim = {
  id, policy_id, owner, loss_id, assessed_value, deductible,
  payout, status, created_utc, paid_utc, reason
}
```

- `id = "claim_" + loss.sequence`；`claims` 以 `loss_id` 为唯一键。**一个损失事件全局最多产生一条理赔**，不因多份保单或多账号重复。
- 匹配规则：`loss.victim == policy.owner`；`policy.product` 与 `loss.kind` 一致；`policy.subject_id` 与损失对象一致；`policy.effective_utc < loss.cause_start_utc`；`policy.expires_utc >= loss.cause_end_utc`；且损失发生时保单仍为有效。
- `payout = min(policy.remaining_coverage, max(0, assessed_value - deductible))`。`assessed_value` 由权威损失行给出，不接受玩家编辑。
- 创建理赔时即从 `remaining_coverage` 预留 `payout`，避免同一保单的多条待赔超过限额；理赔被拒绝时释放预留。
- 赔付成功后置 `paid`；不足时置 `pending`，按 `created_utc, claim_id` 排队，不发行新钱、不让 AI 承诺垫付。
- 理赔表满或待赔队列超过可赔准备金时，先停止售卖新保单，而不是丢弃损失或超发赔付。
- 重复命令、断线重试和同 `loss_id` 重放返回原理赔结果并标记 `duplicate=true`；耐久理赔行是唯一赔付守卫，不依赖 64 条命令窗口或有界分录。

### 准备金

`reserve_statement` 增加 `insurance_cash`、`claims_pending`、`claims_paid` 与按产品分类的限额；`claims` 不再是固定 0。`covered` 表示保险现金是否覆盖当前待赔负债；不足时必须公开显示。

## 反套利与反伪造约束

| 套利/伪造路径 | 当前为什么可行 | 必要约束 |
|---|---|---|
| 灾后追溯投保 | 灾害时间可由种子推导，结算可离线补算 | 保单必须在 `cause_start_utc` 之前生效；损失行记录原因起止；有已发生损失或已开始的原因窗口时拒绝新保单 |
| 同一损失多份保单 | 同一对象可重复签约 | 同一 `owner + subject` 同时最多一份有效保单；以 `loss_id` 为全局唯一理赔键 |
| 自导自演盗窃 | 所有者主动开启偷菜；小号/熟人可扮演小偷；货物只是转移 | 首版不承保盗窃；若未来承保，必须先有不可自导自演的盗窃规则和不可随意伪造的玩家身份 |
| 只给注定损失的对象投保 | 种子和未来灾害由客户端可推导，损失结果不是秘密 | 可选固定保费保险无法同时公平且不可套利。必须选择：强制/合作社会保险、按同一确定日程定价的保费、或让损失结果不可由客户端推导。否则不实现可选保单 |
| 承保自愿手续费 | 运费/成交费是主动支付并可耐久记录 | 明确除外；只赔货物/作物的真实损失，不赔费用 |
| 玩家自报损失或金额 | 现有命令可由客户端提交 | 损失行只由权威扫描生成；保单/理赔入口不接受玩家提供的损失证据或估值 |
| 同一损失重复理赔/重放 | 命令窗口可淘汰 | `claim.id` 与 `loss_id` 耐久唯一；`paid/rejected` 终态；重放返回原结果 |
| 赔付超过实际损失 | 市场价格和玩家申报可变 | 损失价值在原因时点锁定，按参考价/数量计算，并受 `coverage_limit`、免赔和保单剩余额度约束 |
| 赔后恢复或双重补偿 | 未来可能有维修/公共救济 | 一个损失只对应一条排他理赔；若以后有恢复/公共基金，必须在同一损失行上显式互斥 |
| 贷款违约保险 | 逾期只改状态、可随后还款 | 不作为玩家资产损失承保；如需信用担保，另立银行/公共基金裁决 |
| 小号分散投保/索赔 | 玩家 ID 按安装生成，不抗女巫 | 首版不允许同一损失跨账号；若承保盗窃或身份敏感风险，先补身份/信任模型 |

## 复审触发条件

出现以下任一情况时重开本裁决：

1. P0-A 或 P0-B 落地，并产生耐久、唯一、权威生成的逐笔损失行与真实价值终点。
2. 产品明确选择运输风险保险还是风险模式作物保险，并接受相应的 ADR-013 或 ADR-009 修订。
3. 产品明确可选保险的风险信息与定价语义：强制/合作、按已知日程定价，或不可由客户端推导的损失结果。
4. 所有可保资产都有权威价值来源（当前只有六种商品有 `base_price`）。
5. 若未来承保盗窃，身份模型能证明小偷不是所有者或关联账号；当前标识不满足。
6. 理赔队列、保险现金科目和 `reserve_statement.claims` 的设计获得批准；当前 `claims` 固定为 0 只是占位。
7. 出现长期世界损失行超过有界表、或旧经济文档无法按空 `losses/insurance` 恢复的真实存档。

## 受影响规格

- [经济与金融](../systems/economy-finance.md)：保险只赔已登记受保损失、风险路线需显式同意、赔付资金来源与排队。
- [自然系统](../systems/nature.md)：温和模式保护成熟成果；风险模式与损失需独立裁决。
- [ADR-009](ADR-009-disasters.md)：若选择 P0-B，必须修订“灾害只改湿度、不毁作物”的决策与后果。
- [ADR-013](ADR-013-limited-logistics.md)：若选择 P0-A，必须重开“无丢失、无风险路线、无保险”的边界。
- [ADR-014](ADR-014-double-entry-ledger.md)、[ADR-017](ADR-017-bank-loans.md)：新增保险现金科目、保费/赔付分录与 `claims` 负债，不改变余额权威。
- [M8 PLAN](../milestones/M8/PLAN.md)：M8-03 在 P0 完成前保持阻塞；完成 P0 后仍需单独验收保单、免赔、限额、唯一赔付与追溯投保拒绝。
