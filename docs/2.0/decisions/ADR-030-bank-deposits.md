# ADR-030 · 银行存款与准备金拒绝

- 状态：采纳（2026-11-16），M8 存款纯规则切片实现完成；未验收
- 关联：[M8 RECORD-16](../milestones/M8/RECORD-16-deposits.md)、[经济与金融](../systems/economy-finance.md)、[M8 PLAN](../milestones/M8/PLAN.md)、[ADR-014](ADR-014-double-entry-ledger.md)、[ADR-017](ADR-017-bank-loans.md)

## 背景

ADR-017 的复审触发条件写明了“引入存款或银行其他支出时重开本裁决”。M8-05 压力模拟也把“存款挤兑”“存款负债”“准备金率不足时的正式处置流程”列为未覆盖项；`reserve_statement()` 的 `claims` 当时固定为 0，报表无法表达任何真实负债。

本裁决只重开银行现金口径这一部分：允许玩家把现金存入规则银行，银行因此产生可支付的存款负债；提款只使用银行真实现金，现金不足时具名拒绝。本切片仍是纯规则，没有命令接线、UI、网络或时钟。

## 决定

### 1. 存款是负债，不是第二套钱包

`economy.deposits` 只保存债务：

```text
economy.deposits = {
  accounts: {<player_id>: {principal: int, deposited_utc: float}},
}
```

- `principal` 是银行欠该玩家的本金；`deposited_utc` 只记录最近一次成功存入的时刻，用于展示，不参与任何计息或到期判断。
- 余额权威仍是 `economy.accounts[player].cash` 和 `economy.bank.cash`（ADR-014）。存款表没有被任何消费路径当作可花费金额，也没有第二套冻结额。
- 存入把真实现金从玩家账户转到银行现金；取款反向。金额范围 10..1000 COIN，单账户本金上限 1000 COIN，最多 256 个存款账户，命令 id 共享经济命令的 64 条有界窗口。
- 存款人不接受 `@world` 与 `org_` 组织账户：前者不是玩家，后者的余额必须与公共基金文档一致，绕过基金会把两处记录拆开。

### 2. 不付利息

ADR-017 明确“不引入复利/利息”，本切片只做本金。固定利率会把一笔存款变成随时间增长的赔付义务，需要自己的资金来源、到期与计提规则；这些都不在当前范围。存款表因此没有利率、期限、到期或应计字段，`deposited_utc` 也不产生任何派生存款。

### 3. 每笔存取写一条平衡分录

新增 `deposit_in`、`deposit_out` 两种业务事件，事件 id 就是命令 id；它们不在 `Ledger.RESERVED_EVENT_PREFIXES` 中，用户命令 id 可以和它们同名，但同一事件 id 在活跃日志中只能出现一次：

```text
deposit_in   借 bank              贷 account:<player>
deposit_out  借 account:<player>  贷 bank
```

因此 `total_cash` 与 `issued` 都不变：存款不是发行，取款也不是销毁。

### 4. 银行现金不变量改为含存款负债

```text
bank.cash == capital - 未结清本金合计 + 已收费用合计 + deposits_liability
```

`deposits_liability` 是存款表所有 `principal` 之和，由行派生、不另存。`Economy.valid` 的 `_bank_consistent()` 强制这条等式，因此改动银行现金、贷款表或存款表任意一处而不改其余部分都会被拒绝。银行未开市时，账面上不能有贷款或存款。

### 5. 准备金报告

`reserve_statement()`：

- `claims` 现在是真实存款负债，另附 `deposits`（同值）与 `deposit_accounts`（账户数）；
- `reserve` 是 `bank.cash`，即银行自己的现金，而不是所有持有人现金之和；只有银行现金能支付存款人；
- `covered = reserve >= claims`，所以在贷款把银行现金借出后它会诚实地翻转为 false；
- `total_cash == issued` 的对账关系不变，存款不出现在发行或销毁任何一侧。

`reconcile()` 增加 `deposits` 字段（负债报告值），仍按科目逐项比较「账本余额 == 权威余额」，银行现金的账本余额仍等于 `bank.cash`；存款负债是报表项，不是新的账本科目。

### 6. 准备金不足时具名拒绝

`withdraw()` 在 `bank.cash < amount` 时返回 `insufficient_reserve`，不改任何余额、分录或存款行。这条规则的含义固定为：

- 银行可能已经把部分存款贷出，现金会真的用完；
- 先到者的提款全额支付，受保护的是尚未被满足的剩余存款人，而不是把银行透支到所有人的债权都无法兑付；
- 没有“按比例限流”或“固定准备金率”规则：固定比例会永久锁死最后一段存款，且需要额外参数与调参依据；当前只需要可解释的确定性边界。

被拒的存款人保留完整本金，等贷款还款、存款增加或新的银行资本到账后可以再取。拒绝是政策边界，不是对存款人的惩罚或没收。

### 7. 幂等与边界

- 存取命令共用 `economy.command_results` 的 64 条窗口，与 `pay`、贷款一致；同 id 同参数返回首次结果（`duplicate=true`），同 id 换参数返回 `command_conflict`。
- 活跃日志的 `event_id` 唯一性是第二道守卫：窗口淘汰后，只要分录仍在，同一 id 仍返回 `duplicate_event` 且不移动现金。
- 存款没有自己的耐久业务行（一笔本金行无法区分 50 与 90 的存入），因此窗口与日志都淘汰后旧 id 仍可能再次移动现金。这与 ADR-014 §6.1 已记录的 `pay` 边界相同；在命令/网络接线前必须补耐久守卫或时间窗，本切片不对外暴露。
- 旧文档没有 `deposits` 键时按空表读取，`valid()` 通过，恢复时补空形状、不发明存款或现金。反向不成立：银行真的持有存款时删掉该键会让 `bank.cash` 等式不成立，必须拒绝，不能把负债当成 0 隐藏。

## 为什么不是另一侧

- **不建独立的存款钱包**：存款现金必须与账户、商人、托管、银行一起被 `total_cash` 和检查点解释。
- **不付利息**：没有资金来源与到期规则时，任何利率都会形成无法解释的银行支出。
- **不按比例支付、不设准备金率闸门**：需要在挤兑时冻结部分存款人，规则复杂且没有调参依据；全额支付 + 现金不足具名拒绝更简单也可解释。
- **不把存款当发行**：那会让 `issued` 随存款增长，破坏 ADR-012 的净发行口径。
- **不用存款表做命令幂等**：本金行不是命令行，会被后续存取合并；必须用命令窗口，这是本切片明确记录的剩余风险。

## 后果

- 新增 `Game/farm/deposit_state.gd`（纯规则）；`Economy` 增加 `deposits` 子文档、旧档空形状与归一化、`deposit_cash` / `withdraw_deposit` / `deposits_liability` / `deposit_principal` 入口，以及新的银行等式、准备金与对账字段；`Ledger` 增加两种业务事件。
- 没有改动 `FarmState`、`FarmCommand`、世界权威、场景、UI 或网络；农场格式仍为 27，`deposits` 只在既有 `economy` 子文档内。
- 未接入命令、UI、网络；未做存款利率、保障基金、按比例兑付、挤兑队列或多银行。
- 已有存档（无 `deposits` 键）实测可正常 `valid()` 并恢复为空表。

## 复审触发条件

出现以下任一情况时重开本裁决：引入存款利息或到期；引入按比例兑付、准备金率参数或存款保障基金；银行出现除贷款、还款、存款、取款之外的现金路径；存款接入命令/网络/UI 并需要耐久幂等；或旧文档在没有 `deposits` 键时无法解释真实存档。
