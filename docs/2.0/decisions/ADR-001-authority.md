# ADR-001 · 一个世界一个权威写入者与有限迁移

状态：产品边界已确定；协议和实现待 M0/M4 验证。日期：2026-11-14。

## 问题

同一农场需要在 Windows/macOS、三模式和未来服务器间持续存在。若每个模式独立保存或客户端可自行上传余额，将产生重复财产和分叉。旧 Demo 当前不承诺历史兼容，而新产品明确要求数据可携带。

## 决定

单机世界由本地规则实例写入，共享世界由服务器写入；其他端只持有缓存并提交命令。导出携带稳定身份和版本，迁移共享世界采用停写与代次切换。个人持有数据不等于可把共享资产复制到其他经济体兑换。

v27 列为一次性导入来源目标，原件不改写；不扩展为全历史兼容。2.0 发布格式建立明确升级路径和失败恢复。本文确立产品目标，不声称当前 farm_store 已支持目标格式。

## 备选与代价

每模式一份状态实现简单但不能保证连续性；客户端最终权威便于离线但不适合共享资产；全量跨服资产互认增加双花与管理成本，当前不采用。唯一写入者牺牲共享世界断网时的写能力，换取明确的一致性与恢复模型。

## 证据与生效范围

现有 FarmState 已承担权威种植状态，FarmStore 已有备份和冲突检查，可作为渐进演进起点。M0 验证规则重放、v27 映射与中断导入；M4 验证迁移、代次和重连。

旧 AGENTS/rules 对 Demo 的不兼容约定继续适用于旧开发数据；本次用户明确要求的 2.0 目标由[数据契约](../05-DATA-AND-NETWORK.md)限定。工程进入 M0 时针对实际实现同步相关规则，不能批量删除历史依据。
