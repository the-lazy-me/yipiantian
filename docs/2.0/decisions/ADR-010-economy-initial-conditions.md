# ADR-010 · 经济初始条件：商品、货币与 Demo 转换

- 状态：采纳（2026-11-15），M7-01 实现完成；报价、订单与撮合仍待 M7-02/M7-03
- 关联：[M7-01 记录](../milestones/M7/RECORD-01-economy-initial.md)、[经济与金融](../systems/economy-finance.md)、[M7 PLAN](../milestones/M7/PLAN.md)、[ADR-005 物资归属](ADR-005-player-bags.md)、[ADR-006 住宅首版](ADR-006-housing-slice.md)

## 背景

M7-01 要求先确定少量商品、货币发行与回收、Demo 内容转换与库存所有权，并保证“所有初始资源有来源，重复转换不增发”。当前工程的实际状态是：

- 作物收获已经进入玩家口袋（`bags`）或匿名时的公共 `inventory`，归属规则由 ADR-005 固定；没有第二种库存。
- 种子在 Demo 中无限供应；住宅只有工期，没有材料账本（ADR-006）。二者都没有有限来源，不能直接变成可出售库存。
- 世界包信封里有一个 `money: {currency, minor_units}` 字段，但 v27 导入一直写成 0，运行中的农场快照没有钱包，也没有任何发行或账本。
- 农场文档的键集合由 `FarmState._valid_snapshot` 精确校验，v27 导入器另有一份 `KNOWN_FARM_KEYS`；新增持久字段必须同时同步，否则合法存档会被判损坏或导入结果与运行时形状不一致。

如果先做市场报价，再补“钱从哪里来、货归谁”，M7-02 的预留与 M7-03 的成交会建立在两套库存或凭空增发的货币上。因此本裁决只建立最小初始条件，不进入撮合、订单簿和物流。

## 决定

### 1. 商品集合：六种现有作物，来源只能是种植

首批商品为 `greens`、`spinach`、`radish`、`carrot`、`celery`、`garlic`。它们覆盖叶菜、根菜、茎菜和香辛菜四组，也覆盖约 30 分钟到 120 分钟的生长区间。

| 商品 | 来源 | 当前去向 | 参考价（COIN） |
|---|---|---|---|
| `greens` 青菜 | 地块种植并收获，每株 1 篮 | 厨房、喂动物、邻里面包、M7-02 出售 | 6 |
| `spinach` 菠菜 | 同上 | 厨房、喂动物、邻里面包、M7-02 出售 | 9 |
| `radish` 白萝卜 | 同上 | 厨房、邻里面包、M7-02 出售 | 18 |
| `carrot` 胡萝卜 | 同上 | 厨房、邻里面包、M7-02 出售 | 24 |
| `celery` 芹菜 | 同上 | 厨房、邻里面包、M7-02 出售 | 20 |
| `garlic` 青蒜 | 同上 | 厨房、邻里面包、M7-02 出售 | 14 |

- **不纳入种子。** Demo 的种子没有有限来源，计入市场会形成无成本增发；等种子有真实产出与消耗规则后再另裁决。
- **不纳入建材。** 住宅目前只有工期，没有材料扣减（ADR-006）。先发明木料／石料会同时与 M7 的定价和 M5 的住宅验收冲突。
- **不纳入 `luffa` 等其余七种作物。** 首批只定价六种，以保持价格面可解释；`luffa` 是唯一的棚架作物，供给机制与地块作物不同，而且没有厨房或动物吃法。其余作物仍是真实的食物、赠礼和厨房原料，留待 M7-02 扩大商品面时再评估。
- 参考价是 M7-02 价格区间的输入，不是成交价，也不代表已平衡的数值。

**所有权。** 商品不复制到第二张库存表：玩家口袋仍是个人库存，公共 `inventory` 仍是世界库存，经济视图只按商品目录过滤它们。这是 ADR-005 的直接延续，也避免 M7-03 同时提交两份库存。

### 2. 货币：整数 COIN，发行只走一次性开户命令

- 币种沿用世界包已有的 `COIN`，金额是整数最小单位；不引入小数、汇率或第二种货币。
- **唯一发行入口**是 `open_account`：每个具名玩家一次性获得 `OPENING_GRANT = 120 COIN`。这是实验参数，只用于让玩家能参与前几笔交易，不承诺长期物价水平。
- 发行由权威从连接解析出的 `owner` 决定，命令本身不携带可冒领的所有者；同一玩家换一个命令 id 再开户返回 `already_granted`，不会二次发行。
- **Demo 转换不发行货币。** 转换只登记已有货物，货币必须来自明确的开户命令。
- **购买是转移，不是销毁。** `pay` 只在两个已开户账户之间移动已经发行的货币；买方余额减少、卖方余额增加，`issued` 与全服现金总额都不变。M7-02 的成交付款和 M7-03 的费用都建立在这个原语上；手续费、税费等真正减少货币供给的回收项留给后续裁决。
- 因此当前不变量是：`sum(accounts.cash) == issued`，且只有 `open_account` 能增加两边；`pay` 与 `convert_demo` 都不改变 `issued`。

### 3. Demo 转换：登记已有库存，不搬货、不重复

`convert_demo` 从**当前农场快照**读取商品目录内的正数库存：

- 每个具名玩家的 `bags[player_id]` 登记为该玩家的开库存量；
- 匿名收获所在的公共 `inventory` 登记到保留所有者 `@world`；
- 目录外的作物（例如 `lettuce`）不进入经济账本，仍按原来的厨房、动物和赠礼规则使用。

转换**只写一条审计记录**，包含命令 id、来源摘要（规范化 JSON 的 SHA-256）、每个所有者的商品数量、总量与时间；不移动、不复制、不删除任何作物，也不改玩家存档里的其他字段。`@world` 不是合法的玩家 id 格式，玩家无法占用这个键。

一次世界只允许一次转换：

- 同一 id、同一来源摘要重试 → 返回原结果与 `duplicate=true`，不叠加拿取；
- 同一 id、来源摘要变化 → `command_conflict`，不产生第二份记录；
- 换一个 id 再转换 → `already_converted`；
- 空世界可以登记空开库存；此后新增的收获属于正常生产，不会重新打开转换。

### 4. 账本：经济子文档与农场快照同一次提交

经济状态作为农场文档的可选键 `economy` 保存：

```text
economy = {
  currency: "COIN",
  sequence: int,
  issued: int,
  accounts: {owner: {cash: int, granted: bool}},
  conversion: {} | {id, digest, owners, goods_total, at_utc},
  command_results: {id: {payload, result}}
}
```

- 与 `bags`、`inventory` 在同一个 `FarmState` 快照里，由 `FarmStore` 一次写盘；M7-03 的资金与商品可以在同一个候选快照中提交。
- `command_results` 是与农场命令账本同量级的有界幂等窗口（64 条），用于重试回放；`accounts[owner].granted` 与 `conversion` 是持久标记，即使窗口淘汰旧 id，开户和转换也不会再次发行或转换。
- `sequence` 只在新命令被接受时递增一次；回放、拒绝和冲突都不递增。
- `pay` 的幂等目前依赖有界窗口。M7-03 的成交确认或订单 id 必须另带耐久记录，不能仅靠这个窗口；这是本切片明确的边界。

### 5. 存档兼容：可选键，不做迁移机器

- 农场格式版本保持 `27`；`economy` 是像 `bags`、`theft`、`buildings` 一样的可选键。
- 旧快照恢复时得到空经济（无账户、无发行、无转换），不会自动发钱，也不会被覆盖成新文件；下一次正常保存才写入该键。
- `FarmState._valid_snapshot` 的键数与 `economy` 校验、`FarmState.restore_snapshot` 的默认值与整数归一化、`V27Importer.KNOWN_FARM_KEYS` 已同步。格子形状没有变化，因此 `valid_cell_snapshot` 不需要改。
- 不写旧存档迁移器、旧版读取分支或兼容测试；这是早期开发阶段的既定约定。

### 6. 世界包 `money` 字段不是实时权威

`world_package.gd` 信封里的 `money` 继续作为 v27 导入信封字段（导入时初始化为 0），不承载实时余额；实时钱包在 `snapshot.economy`。M7-02 若要让导出携带余额，应明确把它定义为聚合镜像或移除，不能两个字段各自独立变化。

## 为什么不是另一侧

- **不把商品搬进独立的 `economy.accounts[owner].goods`**：会与 `bags`/`inventory` 形成两份库存，厨房、动物、赠送和 M7-03 交割都要同时维护两处；现有归属已经正确，缺的只是价格与货币。
- **不把经济放进独立 `economy.json`**：M7-03 要求资金与商品同时提交，跨两份文件无法保证原子性；放进农场快照可以直接复用 `FarmStore` 的临时文件替换、冲突检测和恢复路径。
- **不把所有 13 种作物一次定价**：商品面越小，M7-02 的报价和 M7-05 的调节越可解释；没有当前去向的货物先不进市场。
- **不让转换自动发钱**：转换是“登记已有库存”，发钱是“发行”，两者混在一个命令里会让重复执行和审计都变复杂。开户与转换分开，各自有明确的幂等标记。
- **不做手续费/税**：当前没有成交，先引入回收项只会增加没有真实数据的参数；M7-03 成交与 M8 公共金融再决定回收比例。

## 后果

- 农场快照多一个可选 `economy` 键；旧档可读，读后不会自动获得货币。
- 世界包的内容摘要包含农场快照，因此新增 `economy` 键会改变新导入／导出的 `world_id` 与 `farm_id`；已有导出不回溯重算，早期阶段不做标识迁移。
- 新增 `Game/farm/economy_catalog.gd`（纯数据）、`Game/farm/economy_state.gd`（规则与账本）、`Game/farm/owner_id.gd`（与 `FarmState` 共用的所有者格式）。
- `FarmState` 暴露 `economy_open_account`、`economy_convert_demo`、`economy_pay`、`economy_cash`、`economy_issued`、`economy_total_cash`、`economy_goods`、`economy_account` 与 `economy_snapshot`；这些是 M7-02 的最小接口，不是网络命令。接到联机命令边界还需要新增命令种类与角色权限，留给 M7-02。
- 没有 UI、HUD、网络消息、订单、预留、撮合、物流、利息或旧档迁移。
- 参考价、开户金额和商品子集都是实验参数；M7-05 必须用真实供需实验重新评估，不能把本文数值当作已平衡结论。

## 复审触发条件

出现以下任一情况时重开本裁决：M7-02 需要按品质、批次或仓储位置拆分商品；种子或建材获得有限来源；需要真正的货币回收（手续费、税、公共支出）并改变 `issued` 语义；跨区域物流要求在途库存；M7-03 的成交幂等无法只靠有界窗口；或者真实供需实验证明六种商品、参考价或开户金额使基本生活不可维持。
