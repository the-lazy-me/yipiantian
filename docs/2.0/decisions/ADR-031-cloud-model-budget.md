# ADR-031 · 云端模型预算：预留、只对成功计费与确定性回退

- 状态：采纳（2026-11-16），M9-04 预算与回退规则切片实现；真实云接入、持久化与 UI 未做
- 关联：[M9 PLAN](../milestones/M9/PLAN.md)、[M9-04 记录](../milestones/M9/RECORD-06-cloud-budget.md)、[ADR-020 模型任务与调度](ADR-020-model-task-scheduling.md)、[NPC、商人与混合 AI](../06-AI-SYSTEM.md)

## 背景

[06-AI-SYSTEM](../06-AI-SYSTEM.md) 已经规定云端默认关闭、启用前展示供应商/数据类型/预算/停用方式、只发送角色所需上下文、按调用前估算预留预算、完成后记实际用量、余额不足不启动新请求、并发请求共享预算、超时也要处理供应商可能已计费的状态。M9-04 要求“授权、最小上下文、费用预留、实际用量记录与硬预算”，验收是“断网/额度耗尽自动回退；并发请求不能越过预算”。

在接入任何真实供应商之前，需要先冻结一组与供应商无关的规则：谁可以发起、用什么单位记账、估算值何时变成实际值、失败是否退款、周期边界如何处理尚未结算的调用，以及预算与可用性同时失败时先报告哪一个。否则真实接入时这些语义会被供应商的计费口径反向决定。

本裁决只覆盖费用与回退规则。**最小上下文**已由 [ADR-020](ADR-020-model-task-scheduling.md) 的 `visible_context` 白名单、8192 字节与 8 层上限冻结，本裁决不另建第二套上下文规则；授权开关只决定“是否允许云端”，不重复校验上下文。

## 决定

### 1. 云默认关闭，授权是显式布尔开关

- 预算文档的 `config.enabled` 默认 `false`；未启用时 `authorize` 返回 `cloud_disabled`，`choose_backend` 返回 `rules`。
- 开关只在一个地方（`config.enabled`）维护，不把“有余额”“有网络”当作隐式授权。

### 2. 金额是调用方定义的抽象非负整数

- 所有金额字段（`hard_limit`、`request_limit`、`estimate`、`actual_cost`、`total_cost`）都是非负安全整数；单位（分、厘或供应商积分）由调用方决定，规则层不做货币换算。
- 不用浮点记账。整值浮点（JSON 往返）在校验时接受，但运算与比较使用整数语义。
- `initial_state` 的默认值（周期 86400 秒、硬上限 1000、单请求 100、并发 2）是实验边界，不是供应商报价。

### 3. 授权只预留，不记已用

- `authorize(state, request_id, estimate, now_utc)` 在通过全部门禁后把估计值写入预留表；`used.cost` 只在结算时变化。
- 可用额度 = `hard_limit − used.cost − Σ预留估计值`；不足则 `over_budget`。
- 单请求估算超过 `request_limit` 返回 `over_request_cap`；预留数达到 `concurrency_limit` 返回 `over_concurrency`。两者先于预算检查之后的并发检查分别具名，调用方可以给出不同提示。
- 所有拒绝都不修改输入文档，也不追加事件。

### 4. 只有 `ok` 计费，失败释放预留

- `settle` 的 `outcome` 只接受 `ok`、`failed`、`timeout`、`offline`、`cancelled`。
- `ok`：把实际费用 `actual_cost` 计入本周期已用与 `total_cost`，释放预留。
- 其余四种：释放预留，`charged=0`，不增加已用。理由是失败、超时、离线与取消都没有可归因的成功服务；把估算值计入已用会让一次断网永久吞掉额度，并把预算变成“尝试次数”。`actual_cost` 仍写入 `settled` 行作为对账证据。
- 真实供应商可能在超时后已计费。规则层不猜测这笔费用是否发生，只保留调用方报告的金额；把它补记到哪个周期或科目是宿主与对账流程的决定，不由 `settle` 自动推断。

### 5. 同一 `request_id` 是幂等键

- 已结算 id 再 `settle` 返回首次结果（`duplicate=true`，不产生新文档、不二次计费）。
- 已预留或已结算 id 再 `authorize` 返回首次结果；换估计值复用同 id 返回 `command_conflict`。
- 重放解析先于开关与预算门禁：云在重试期间被关闭或额度用完，同一 id 的重试仍应得到首次结果，而不是“未授权”。
- 结算从未授权或已被重放窗口淘汰的 id 返回 `unknown_request`。窗口有界是明确语义，客户端需要把超时重试放在窗口内。

### 6. 周期切换保留未结算预留

- `rollover(state, now_utc)` 把周期起点推进到 `now_utc` 已到达的最近整周期，清零 `used.cost`；`total_cost` 跨周期累计不清零。
- 未结算预留不被丢弃，也不被“洗白”：预留行保存创建时的 `period_start_utc`，跨周期后继续占用额度与并发，结算时按真实结算时刻计入当时所在周期。
- 周期已到终点时 `authorize` 返回 `period_elapsed`，要求调用方显式 `rollover`；`settle` 同样拒绝已关闭的周期，避免把晚到完成的费用记进已经结账的账期。模块不隐式切换周期。
- 不保留已结算落地行以外的历史周期账目；跨周期审计依赖 `total_cost` 与调用方自己的账单。

### 7. 回退是纯函数，优先级固定

`choose_backend(budget_state, now_utc, cloud_available, local_available)`：

```text
无效文档/时间            -> rules
enabled=false           -> rules（cloud_disabled）
cloud_available=false   -> local（有本地后端）或 rules（cloud_unavailable）
达到周期终点            -> local/rules（period_elapsed）
已用+预留 >= 硬上限     -> local/rules（budget_exhausted）
预留数 >= 并发上限      -> local/rules（concurrency_full）
其余                    -> cloud
```

- 云不可达优先于预算耗尽：调用方需要区分“断网”与“没钱”。
- 本地后端是否可用由调用方传入布尔标记；函数不探测进程、不读配置、不读全局。
- 回退只决定下一个任务走哪个后端，不修改预算文档；调用方仍须在真正发起云端调用前 `authorize`。

### 8. 文档有界且严格校验

- 预留表受 `concurrency_limit`（上限 64）约束；落地表最多 256 行；事件日志最多 256 条，按时间淘汰最旧。
- `valid()` 要求顶层与各表键集精确、所有计数为非负安全整数、枚举合法、`charged` 与 `outcome` 一致、同一 id 不同时出现在预留与落地表、预留所属周期不晚于当前周期、`total_cost >= used.cost`。
- 事件只记录身份、结果、金额与时刻，不记录提示词、模型输出或用户原文。

## 为什么不是另一侧

- **不按估算值计费**：估算值偏大会永久扣掉未使用的额度，偏小则在长期运行中越过硬预算。预留占用 + 实际结算同时解决两个方向。
- **不为失败计费**：把失败尝试计入已用会让预算度量“尝试”而不是“开销”，并让断网成为惩罚；供应商超时计费是宿主对账问题，不是规则应当猜测的语义。
- **不丢弃跨周期预留**：丢弃会让周期边界前的并发请求在新周期再开一批，等于用时间边界绕过并发上限。
- **不隐式 rollover**：隐式切换会让“授权”带有第二个副作用，重放与审计都不再确定；显式 `rollover` 保持命令语义。
- **不在预算模块内探测网络或本地进程**：那会把规则测试变成环境测试。可用性标记由真正的宿主/适配器提供。
- **不新建第二套上下文规则**：ADR-020 的白名单与字节/深度上限已经冻结最小上下文；M9-04 的“最小上下文”在此引用，不复制。
- **不持久化**：本切片只冻结规则；存储位置、原子写入与跨启动恢复属于宿主接入，在没有真实云适配器前提前做会固定错误的数据生命周期。

## 后果

- 新增 `Game/ai/model_budget.gd`、`Game/ai/model_fallback.gd`、`tests/model_budget_test.gd`，以及本 ADR 与 M9-04 记录；未修改既有 AI 模块、农场/世界/UI/平台代码、其他里程碑或 `rules/project-context.md`。
- 预算文档与调度器尚未接线：真实适配器必须在提交任务前 `authorize`、完成后 `settle`，并按 `choose_backend` 选择后端；当前调度器仍只有单队列与本地后端。
- 没有任何真实供应商、网络、密钥或付费调用；`actual_usage`/`actual_cost` 全部由调用方注入。
- 事件与落地表有界意味着旧 id 在窗口淘汰后无法再识别为重放；客户端重试窗口必须小于该界，或由宿主提供更大的持久重放表。
- 金额是抽象整数，真实接入时需要定义估算函数（token、字节或供应商报价）、单位与周期长度；这些都还不是实测结论。
- 未处理多客户端共享同一预算文档的并发写；写时复制接口假定由单一权威串行调用。

## 复审触发条件

出现以下任一情况时重开本裁决：

- 接入真实云供应商，需要定义估算函数、计费单位、账单对账或供应商超时已计费的处理；
- 预算文档需要持久化、跨启动恢复或多写者并发；
- 需要更长的重放窗口或跨周期审计报表；
- UI 需要展示预算、回退原因或提示玩家充值/切换模式；
- Windows 实机或双平台测试暴露不同的时间/金额行为。
