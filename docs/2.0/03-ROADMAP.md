# P0 与 M0–M13 长期研发路线图

状态：规划已编写；P0 调查与文档部分已开展，技术原型未完成；M0–M13 均计划中。阶段名称沿用前序讨论，不据本文宣称工程已升级为 2.0。

## 优先级与阶段价值

P0 是前置阶段，不与缺陷严重度混用。工作优先级使用“阻塞 / 核心 / 后续”：阻塞项决定是否合法、是否可行或会否丢数据；核心项形成该阶段可用成果；后续项不阻塞较早成果。当前优先 P0 的许可、数据、Mac 与能效原型，再进入 M0。模型和战争不阻塞个人农场的首次跨平台交付。

| 阶段成果 | 里程碑 | 可独立使用的价值 |
|---|---|---|
| Desktop Alpha | M0–M2 | 可迁移、跨平台、三模式的个人桌面农场 |
| Village Beta | M3–M5 | 自建服务器、混合平台互访与多人家园 |
| Living World Beta | M6–M8 | 天气、生产、市场与金融形成因果 |
| AI Society Beta | M9–M10 | 有限预算下有记忆、自主行动的居民 |
| Civilization Sandbox 2.0 | M11–M13 | 可选治理与冲突、长期维护与发行 |

## 关键路径与可提前研究的工作

工程关键路径为 P0→M0→M1→M2，以及 M0→M3→M4→M5。M3 的无头原型可在 M1 的平台工作期间研究，Village Beta 的交付仍等待双平台和基础生活稳定。M6→M7→M8 依次建立自然、交易和金融；M9 的模型实验可提前，正式居民 M10 必须等待调度与经济权限可用。

M11 依赖地籍所需的建设权限和公共账本，官员的模型表现可后接；M12 依赖 M11 的规则与执法。M13 汇合全部必需门槛。艺术、声音、开源研究和测试贯穿各阶段，但只生产当前切片所需的代表内容。

## 计划如何更新

远期步骤已给出可执行拆分，具体数值和技术选择在进入阶段前用证据收敛。不得在未验证依赖时同时启动全部里程碑，也不因一个后期候选失败重写所有早期工程。变更时先更新权威规格/ADR，再改受影响阶段和风险，不复制另一套路线图。

不预设开发完成日期。P0 原型和首批 M0 工作包完成后，用实际耗时、返工、设备与许可阻塞估算下一阶段；日期承诺需要同时包含实机验收和发行准备。内容数量增长不能代替能力完成。
