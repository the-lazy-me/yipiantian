# 技术架构总纲

状态：目标边界已确定；部署、存储与轻量宿主的具体实现待 P0 原型裁决。[现有代码](research/BASELINE.md)仍是当前实现依据。

## 从现有工程演进

保留 Godot 4.7.2 工程、GDScript 规则、正式资产和 Windows 宿主。`Game/farm/farm_state.gd` 已隔离部分状态，`farm_store.gd` 负责保存；从一条种植或收获调用链建立命令边界，再逐项迁移其他操作。`main.gd` 按实际职责拆分，不因体积大就全面重写，不先创建空的 ECS、微服务或插件体系。

| 边界 | 负责 | 不负责 |
|---|---|---|
| 客户端呈现 | Godot 场景、输入、预览、可访问性、画质 | 最终资产裁定 |
| 平台外壳 | 窗口层级、遮挡、电源、托盘、启动与恢复通知 | 直接读写世界账本 |
| 世界规则核心 | 时间推进、命令校验、资源与权限、事件结果 | GPU、模型推理、网络供应商 |
| 持久化边界 | 原子提交、快照、恢复、迁移 | 根据 UI 动画猜测结果 |
| 联机边界 | 身份会话、命令传输、版本协商、订阅同步 | 信任客户端自报余额 |
| AI 调度 | 可见上下文、推理预算、建议与取消 | 直接写状态或绕过权限 |

## 单一权威执行链

输入转成命令，绑定操作者、世界、幂等标识、目标与前置版本。权威执行者先推进相关状态到命令时间，检查权限和资源，在一个持久化提交边界内产生结果与事件，成功后向客户端返回已提交版本。失败返回明确原因；展示可预测但必须可撤销，不能先把未提交收入当作可花余额。

单机由本地规则实例拥有世界；共享房由服务器拥有世界。客户端与轻量外壳可以缓存，但不能同时成为写入者。跨进程桥接若采用，只开放命名操作和限定数据，禁止通用执行接口。

## 三模式与深度休眠

| 模式 | 玩家能力 | 呈现与资源策略 | 状态职责 |
|---|---|---|---|
| 观赏 | 看昼夜、天气、居民与变化摘要 | 缓存画面，必要动画低频绘制；静态时按变化刷新 | 订阅同一世界 |
| 轻量桌面 | 简单种收、查看集市、短交互 | 轻量界面与局部呈现；复杂建设显式转入全量 | 提交同一种命令 |
| 全量游戏 | 自由镜头、建设、探索、组织及战略 | 完整 3D，按设备档位调画质 | 不拥有额外经济权威 |
| 深度休眠 | 暂无主动交互 | 锁屏/熄屏/完全遮挡后停绘制，取消非必要推理并卸载可恢复资源 | 恢复时补算或重同步 |

深度休眠是三模式之上的生命周期状态。切换先结束输入手势，确认未提交动作，保存或记录最后已确认版本，再释放表现资源。恢复顺序为确认连接与权威版本、推进或同步世界、重建显示、开放输入。断线时显示缓存时间与离线状态，不能继续提交共享财产变更并伪称成功。

轻量模式究竟采用单 Godot 进程还是原生外壳加规则服务，由 [ADR-002](decisions/ADR-002-runtime.md) 决定。现有 Windows 观赏 30fps、遮挡停绘制和缓存释放是已有基础；2.0 不把这些自动算作三模式、全平台深度休眠已完成。

## 低功耗模拟与服务器

按“下一个有意义的事件”推进：作物阶段、订单到期、天气转换、合同结算决定唤醒点。长离线使用分段解析或有界步进；按天气、规则变化等真实边界分段，不逐帧重放。单次补算设工作预算，超预算分批继续并显式报告进度，不截断应兑现的资产。

无人区域按汇总状态运行，近处视觉从汇总状态派生。先证明聚合前后产出与债务一致，再降低精度。经济账本和权属不以“远景优化”为由近似；物理、粒子和骨骼可仅在可见区域运行。

无头服务从规则入口启动，不加载 3D 场景、纹理或音频。先验证 Godot 无头复用，再决定是否有必要拆出其他语言核心。服务按世界分区，每个世界先采用一个逻辑写入者；规模增长有测量依据后再讨论分片。存储候选与崩溃提交语义见 [ADR-003](decisions/ADR-003-storage.md)。

共享服务器的持续运行与玩家机器休眠分别处理。玩家电脑同时做房主时，系统休眠意味着服务不可达；客户端应提示这一事实，可选择迁往独立服务器，不能承诺房主睡眠时仍实时在线。

## 平台与交付边界

Windows 保留原有图标下层和输入门禁；macOS 先交付正常窗口，再验证桌面展示、Spaces、全屏应用、Dock、权限与多屏。桌面嵌入失败时回退到明确的观赏窗口与主动交互入口，不牺牲窗口版可玩性。[平台与能效验证](architecture/PLATFORM-ENERGY.md)定义试验。

目标客户端为 Windows/macOS；Linux 在 M4 验证服务器，不因此承诺 Linux 图形客户端。支持系统版本、CPU 架构、图形后端和签名策略由实机构建证据写入发布矩阵，不从引擎的通用支持列表推断本游戏已支持。
