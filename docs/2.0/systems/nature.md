# 农耕、生态、气象与灾害

状态：2.0 系统设计；现有逐格种植与 UTC 生长保留，生态数值和灾害未验证。上位依据：[系统总纲](../02-GAME-DESIGN.md)。

## 农耕闭环

地块保存稳定身份、占用作物、播种批次、有效生长、最后结算时刻和照料记录。种子、工具、水与肥是否计入库存由规则版本决定。M0 先保持 Demo 的种植经济语义，M7 引入有限资源后明确转换来源，不把历史无限种子直接变成可出售库存。

播种检查使用权、地块空闲、品种条件及资源；通过后一次扣料并创建批次。浇水先按旧环境结算，再修改环境或本轮照料状态。收获检查成熟和收获权，销毁该成熟批次并生成一次产出；重复请求返回原结果。改种和移除展示损失，取消预览不消耗资源。

收成由品种基础产出、有效生长和已记录环境影响决定。品质先采用少量可解释档位，避免每株生成难以理解的隐藏属性。玩家可查看“为何生长变慢/产量变化”；表现层叶色或模型缩放不参与计算。

## 环境模型

第一版以区域天气加地块湿度为主，温度、土壤肥力与排水在证明能改变有趣选择后逐项进入。降雨补水、蒸发失水、灌溉改变局部状态；昼夜光照的视觉时间与季节农业时间分别记录。现有日照表现不直接升级为每株实时光线追踪。

天气按世界种子和事件序号生成，预报展示有限确定性。已发生天气存为事实，读档不重抽。真实天气映射为可选输入适配器，缓存采用过的输入；服务不可用时沿用已公布的世界天气或显式切换规则，不依赖现实位置才能种田。

生态采用有限资源与栖息地关系表达：植被、水域、昆虫与动物活动影响氛围或可解释的局部生产条件。先使用区域指标，只有玩家能观察并干预时才增加物种细分，避免创建不可维护的完整生物学模型。

## 灾害与恢复

候选灾害为干旱、暴雨、寒潮和局部病害。每种事件具有发生条件、预警、影响范围、强度、持续时间、保护措施和恢复路径。灾害先改变环境，再经农业规则影响生产，不能直接随机清空仓库。

默认温和模式允许减速或降低本轮额外收益，成熟成果与基本住所受保护；风险农业需主动选择，并在播种或购买土地前展示可能损失。长期离线保护由世界规则定义，对同等在线/离线时间使用同一计算模型，保护作为显式规则输入，不用登录状态暗改随机概率。

排水、储水、轮作和保险提供不同应对方式；任何一种都不应成为每天必须操作的作业。事件结束后自动恢复基本生产能力，玩家可自愿加速修复。共享公共设施损坏遵循公共预算和维修规则，不向所有成员强制发任务。

## 结算与实验

输入为起始快照、时间区间、天气事件、玩家动作及规则版本；输出为新地块状态、消耗、产出和解释事件。在线小步与离线分段结算应在声明误差内一致，离散产出和事件次数必须一致。误差预算在 M6 固定，当前不虚构百分比。

M6 实验包含晴雨交替、跨季节、长离线、时间回拨、临界成熟时浇水、重复恢复及灾害关闭。用固定种子对照温和/风险模式，检查无负库存、无重复成熟奖励，且无照料玩家仍能完成基本种收。

进入条件为 M3 的事件与恢复能力；与 M7 的接口只交换已确认产出和可用库存。实施见[M6](../milestones/M6/PLAN.md)。
