# 开源研究方法与选型规则

状态：初始候选与来源已建立，未批量引入依赖。入口：[候选清单](research/CANDIDATES.md)、[上游与资产权利](research/RIGHTS.md)。

## 研究先于重复建设

复杂的桌面生命周期、网络、持久化和模型推理优先研究成熟项目。先写清要解决的问题与现有方案缺口，再筛选候选；不以 Star 数量或演示视频替代适配判断。产品理念仍由本项目宪章决定，生存或竞争游戏的目标结构不直接移植。

每项研究经过来源定位、许可证与版本核对、关键调用链阅读、隔离原型、目标硬件测试和采用决定。初始档案只完成来源级核验，不声称已理解整个代码库。没有进入当前阶段的经济/战略项目先借鉴机制，临近 M7/M11 再深入。

## 研究必须回答的七个问题

1. 要复用的是代码、独立程序、协议经验、机制设计还是视觉资产？分别处理，不能把“参考”含糊地写成“采用”。
2. 哪个固定提交、许可证文件和关键模块支持判断？记录文件级例外、资源许可与依赖许可。
3. 能否与锁定 Godot、Windows/macOS 和自建服务协作？适配工作是否超出自己实现的成本？
4. 空闲时是否新增常驻服务、GPU 工作、网络请求和高内存？能否暂停、取消、卸载？
5. 是否能导出世界与身份，服务关闭后是否仍可自托管？
6. 维护状态如何：近次变更、发布、问题处理与平台支持是否有实际证据？一次新提交不等于健康维护。
7. 如何移除或替换它，迁移数据与长期升级的代价是什么？

## 决策与记录

最终采用类别为“直接采用”“参考实现”“只借鉴设计”“暂不采用”。直接采用必须有许可依据、目标平台原型、明确集成边界和移除方案；参考实现不等于允许复制；只借鉴设计仍需独立表达实现。当前十项初始候选均未因此成为正式依赖。

研究档案保存问题、固定来源、关键路径、实测条件、发现、失败、许可与决定。只有确实查看或运行过的内容写“已核验/已实测”。无法获取提交或许可正文时写缺项，下一轮补证，不猜造版本。引用移动分支的资料在采用前重新固定提交。

## 首轮顺序

P0 优先 Godot 无头与 Mac 导出、Lively 生命周期、Luanti/Nakama 自建世界经验、llama.cpp/MLX 推理边界。AI Town 研究记忆和自主行为；OpenTTD、Unknown Horizons 与 Freeciv 留作经济/政治机制对照，不把它们的强制发展目标带入本项目。

初步筛选每项先完成一轮可回答具体问题的阅读；发现必要能力缺失、许可不符或明显超出资源预算即记录并停止扩展。原型成功后才考虑深度集成，不为完整研究表无限扫描仓库。

## 许可与资产

[GitHub 许可说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)解释公开仓库与许可的区别。复用前按具体文件、版本和分发方式核验；GPL/LGPL、署名、相同方式共享等要求不可由另起进程或删除 LICENSE 自动消除。无法明确时先研究机制，不复制代码进入发行工程。

原项目、字体、博物馆参考、生成服务输出、模型权重与依赖各自建来源链。当前请求明确要求重新核验授权，历史“暂缓商务调查”不作为跳过本轮调查的理由；不自动联络作者、购买授权或替用户作法律承诺。
